# Phase 5 — UX study: the panel's committed design decisions

**Status:** binding design-decision record for P5–P15 · produced 2026-10-12 · owned by P5.
**Consumed by:** P5 (shell composition, spot-checked live per its verification checklist), P6–P10 (pages/satellites), P11–P14 (second baseline), P12 (strip), P15 (audit gates).
**Still open in P5:** the on-page-inspector **strip design brief** (separate checklist row) — this study constrains its language, status vocabulary and interaction counts (`UX-D7`, `UX-D11`), not its visuals.

## TL;DR

Three personas (fixed by the P5 Goal); every _opening question_ is answered at first paint with **0 interactions** on the status bar (`UX-D1`), and every first-tier answer is gated at **≤ 1–2 interactions** (§6 budget table). A Nielsen-10 heuristics audit maps each planned pattern to the verified legacy failure it repairs — 18 observed frictions, `F1–F18` (§5, §4). The per-surface information hierarchy (§7) fixes what is glanceable / one click / hidden. All layout decisions of the P5 shell are recorded as `UX-D1…UX-D15` (§8); later phases trace to these ids, and P15's copy sweep is the only string authority. Change control (§11): a later task may not contradict a decision here without revising this study first.

## 1. Method & sources

- **Verified this round (deskside reads):** legacy `entrypoints/fdt/App.tsx` (fetch machine, menu registry `App.tsx:18-25`, search bounce + route-reset, handler registration inside the data promise `.then` — `App.tsx:40-73`), `components/app/devtools/menu.tsx` (flat text-only link list), `pages/Error.tsx` (recovery = a manual close/reload/reopen card; no retry affordance), `components/app/devtools/FetchingComponent.tsx` (infinite blur pulse, `repeat: Infinity` + 0.5 s entrance), `pages/Fetching.tsx`, `pages/Error.tsx`. Deeper page-level behavior (Detections with magic ids, JS filters, Undefined-References 1000 ms gate, Diagnoser triple-sourced tabs) is taken from the phase docs' code audits — `07-phase-6-panel-pages.md` §"Legacy reference" and `06-phase-5-devtools-panel-shell.md` §"Legacy reference" — which carry the bug refs (#6–#42).
- **Second baseline:** the inspector strip's structure (class-state chips, drag persistence, version status) was audited for the port plan (master plan §9) and will be re-walked design-time by the strip design brief.
- **Standards applied:** Nielsen's 10 usability heuristics (NN/g, canon since 1994); information scent / information foraging (NN/g) — live-state previews beat bare labels ("naked link lists force blind clicks"); WCAG 2.2 (AA contrast 1.4.3/1.4.11, Target Size (Minimum) 2.5.8, Animation from Interactions 2.3.3 / `prefers-reduced-motion`); WAI-ARIA APG — **combobox** for the command palette (arrows cycle with wrap, Home/End, Enter accepts, Esc closes without losing input; `aria-activedescendant` keeps caret focus in the field), **tabs** (roving tabindex; automatic activation chosen — sub-views are cheap to render) — APG pages verified 2026-10-12; Chrome DevTools conventions (keyboard-first population, docking geometry variability) from `developer.chrome.com`.
- **APIs verified against the installed tree:** `chrome.devtools.panels.themeName` exists (typed in `node_modules/@types/chrome/index.d.ts`, since Chrome 59) — basis of §9's owner observation.
- **Method limitation, stated honestly:** no user interviews — the tool ships to WP Rocket's support/QA/engineering workflow, so the personas below are role-based with jobs taken from the P5 Goal and master §8 (support-report audience). The P15 release round re-walks the budget table against real usage; deltas then revise this study.

## 5. Usability-heuristics audit of the planned IA

| Heuristic                                                                                                                  | Legacy failure (`F`s)        | Planned-IA answer (binding)                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 · Visibility of system status                                                                                            | `F1`, `F6`, `F18`            | Status bar (present/version/cached age/platform/freshness), fetching skeletons (not fake delays), stale markers, captured-at timestamps — `UX-D1`, `UX-D13` |
| 2 · Match system ↔ real world                                                                                              | `F15`                        | Feature names exactly as the plugin's settings UI/KB spell them (master §4.12); invented abbreviations never render — `UX-D12`                              |
| 3 · User control & freedom                                                                                                 | `F4`                         | Esc clears search/overlays; retry on error; Cancel-exit semantics per APG combobox; route state survives navigation — `UX-D3`, `UX-D5`, `UX-D9`             |
| 4 · Consistency & standards                                                                                                | `F5`, `F7`, `F10`            | One status vocabulary (§`UX-D7`), one tabs pattern, one appearance model, one motion model — `UX-D6`, `UX-D7`, `UX-D10`                                     |
| 5 · Error prevention                                                                                                       | `F3`, `F12`                  | Reserved routes render disabled-with-tooltip (never a dead end); untrusted payloads validated at the boundary before render — `UX-D9`                       |
| 6 · Recognition over recall                                                                                                | `F2`, `F17`                  | Live-state nav previews, tooltips with label + state, status-bar segments as scent-carrying controls — `UX-D2`                                              |
| 7 · Flexibility & efficiency                                                                                               | `F4`, `F16`                  | Palette (`Cmd/Ctrl+K`), shortcuts + `?`, hash deep-links (bookmarkable), streaming search — `UX-D3`, `UX-D4`                                                |
| 8 · Aesthetic & minimalist                                                                                                 | `F7`, `F10`, `F11`           | Data-first density, one semantic accent, no decorative gradients/pulses; token-only styling — `UX-D6`                                                       |
| 9 · Recognize/diagnose/recover errors                                                                                      | `F3`, `F12`                  | Actionable error states with retry; extension-context-invalidated named explicitly; toasts for side-effect confirmation — `UX-D9`                           |
| 10 · Help & documentation                                                                                                  | `F16`                        | `?` shortcuts overlay; per-page one-line "what am I looking at" copy; empty states explain rather than stare — `UX-D3`, `UX-D9`                             |
| **Context: geometry is variable** (docked bottom = full width; docked right = user-dragged narrow; undocked = free window) | legacy ignored docking       | Container-query morphology + the 480 px glanceability contract — `UX-D2`, `UX-D8`                                                                           |
| **Context: keyboard-first population**                                                                                     | `F16`                        | APG combobox (palette) + APG tabs (sub-nav) + roving focus + focus-on-`h1` route switch — `UX-D3`                                                           |
| **Context: data is the aesthetic**                                                                                         | lists rendered unvirtualized | Monospace/tabular values, virtualization ≥ 100 rows, long-task gates (P6: none > 50 ms, TBT < 200 ms on the 5 000-row fixture) — `UX-D6`, `UX-D13`          |

**Accessibility floor (mechanical, gated in P11/P15):** WCAG 2.2 AA contrast on tokens; Target Size (Minimum) 2.5.8 — compact density never shrinks hit areas below 24×24 CSS px (dense visuals, padded targets); 2.3.3 — all motion disabled under `prefers-reduced-motion`; no wrong-palette flash (appearance resolved pre-mount per master §8).

## 6. Interaction-load budget (the gate)

**Metric:** an _interaction_ = one deliberate click or keypress after the panel reaches ready state; hover, pointer movement and waiting do not count. `0*` = the answer is visible at first paint without scrolling in the accepted geometry (≥ 480 px container width; narrower wraps, never horizontal-scrolls — `UX-D8`). Legacy counts are read off the verified inventory (§4). A gate exceeded in implementation is a defect to fix, not a re-budget.

## 9. Open observations for the owner (decision not required to proceed)

1. **DevTools host theme mismatch:** the panel's default `system` follows the OS, but DevTools itself has its own dark setting — a user with OS-light + DevTools-dark sees a mismatched panel. `chrome.devtools.panels.themeName` (verified typed, Chrome 59+) would allow an optional "Match DevTools" appearance mode. The owner's exactly-three-options mandate (2026-10-12, master §8) stands — flagged only; P9's options row is the landing place if ever adopted.
2. **Undocked first-open geography:** undocked windows can be resized freely; `UX-D8`'s 480 px contract is the test floor, and the P5 morphology thresholds (768 px) were picked so both common geometries hit their intended nav form. If real usage disagrees, revise this study, not ad-hoc CSS.

## 10. What this study does not decide
