# Copy action focus remediation — 2026-10-15

The clipboard audit reproduced a keyboard regression in real Chromium: a delayed complete-source read made the shared copy button natively disabled, moving focus to the document body. The regression is retained unchanged in `tests/e2e/suites/panel-script-copy-audit.spec.ts`.

The copy action now keeps its native button focusable, announces a pending operation through `aria-disabled` and `aria-busy`, and shows the existing busy icon. Its synchronous invocation guard prevents repeat keyboard or pointer activation throughout the source read and clipboard write. It never calls `focus()`, so a user who moves elsewhere during the operation keeps their chosen focus. Generic `Button` loading semantics remain unchanged. Disposal cancels source reads and suppresses feedback from a clipboard write that settles after unmount; a platform clipboard write already submitted cannot be cancelled.

The existing unit assertion requiring native disabling was changed because it pinned the focus-loss defect. The replacement pins focusability, busy semantics, duplicate suppression, and state recovery. The original browser focus regression was not weakened. Additional tests cover repeat activation, user-moved focus, source failure/retry, source cancellation, and late clipboard success/failure after disposal.
