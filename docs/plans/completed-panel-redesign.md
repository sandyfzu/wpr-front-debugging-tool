# Panel + options redesign: shipped P23 and open items

## TLDR

P23 shipped on `feat/p23-panel-redesign` (2026-11-18 → 2026-11-19; base `develop` `ae8bb59`): the devtools panel and the options page were redesigned on the owner-approved [mockup canvas](https://claude.ai/artifact/D7zrRhaseFoB4iaxDXmbcv) (owner rated the old look "3/10"). One top bar replaces the bottom status strip; a labeled sidebar folds to the icon rail; resource lists are calm rows with a master–detail view (side pane ≥ 830 px content, drill-in below) and combinable facets; Detections leads with stat tiles and groups features; tool pages share one settings/result layout; options gets the same system (sticky app bar). **Injected UIs (strip, exclusion overlay, on-page palette) are unchanged** (byte- or pixel-identical proofs per phase). No new dependency.

Status: complete, acceptance receipted ([P23.1](./23-phase-23-panel-redesign.md#p231--acceptance)); **not merged into `develop`** (owner decides when); owner Firefox check open. This record holds the lasting decisions; phase instructions, receipts, audit rounds and test-change rationales stay in Git history (commits `3711de0`…`13844e8`). Code, `scripts/budgets.json`, the [UI bar](../ui-ux-bar.md) and [design decisions](./design-decisions.md) override the figures below.

Superseded (do not reintroduce): the bottom status strip and its 480 px rule; the rail-at-every-width rule (2026-10-13 revision, P5J's rail-only final); 32 px hairline rows and a `CodeBlock` per row; single-select chip filters (`FilterBar`, `filterAndSearch`, default `FilteredList`); the Detections summary strip, whole-card links and Adaptive layout; the RUCSS/Beacon Settings tab; P6's "Detections untouched — no invented search".

## Firefox data collection (P23.3, owner 2026-11-19)

`required: ['none']`, `optional: ['browsingActivity']`; the RUCSS Tester run and the PageSpeed Insights open ask at first use and check every use (revoked → asked again). Neither the DevTools panel nor a content script has Firefox's `permissions` API (namespace scoped to extension pages), so the background checks (`getAll().data_collection`) and shows the Firefox-only `data-consent` page (one tab per tool, focused on a repeat ask), whose Allow calls `permissions.request` in the click handler. The background re-checks before the RUCSS request, opens the PageSpeed analysis tab itself, and the analysis page loads its frames only once allowed (page notice + Allow… otherwise). Declined, or the consent tab closed unanswered → RUCSS shows "Sending the page address was declined" + Ask again; the PageSpeed consent tab shows the decline + Ask again; a grant in one consent tab settles the others; nothing is sent. Known limits: a RUCSS run auto-restarts (forced as it was) only when it waits on its own ask and the grant lands on that same page load — a grant from another tool's consent tab counts (the open RUCSS consent tab settles and sends its own); one heard mid-run or mid-refetch is held until the run lands / the page settles; declined, ask-failed, another load, or a grant while the repeat question is up → the user clicks Run/Ask again; a consent-tab show that hangs and later completes after the bounded wait can leave a second consent tab; a consent tab navigated to a page whose address the background cannot read (`about:`, `file:` — no `tabs` permission) sends no dismissal until it closes (the next ask sees the foreign page and opens a new tab); unverified without real Firefox: bfcache `pageshow` re-check on Back from the consent page. Details: [P23.3](./23-phase-23-panel-redesign.md#p233--injected-reduced-motion--build-hygiene).

- Options Save has no compare-and-set: an outside write inside Save's read → write window is lost (pre-existing, one storage round trip). Re-picking on the page the stale value it shows is not an edit.
- Nav toggle overflows below ≈ 135 px panel height; first sticky band 36 px vs 48 px scroll padding (12 px cosmetic offset); Grouped uses CSS columns (balanced by height, not the board's fixed split); Detections overview skeleton keeps 4 tiles at compact.
- Detections layout choice is session-only (never stored). Other routes' loading subtitles may run 3 lines at 320 px (loading reserves two) → up to 16 px shift when data lands.
