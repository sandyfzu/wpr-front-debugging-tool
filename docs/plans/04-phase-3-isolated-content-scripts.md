## Owner-directed widget redesign (2026-10-13)

The owner tested the shipped widget and rejected it: the report list was visibly open from page load, the marker sat pushed right of it, and a blank full-height column lingered over the controls. All three traced to ONE planted defect, reproduced before touching anything: `known-conflicts.css` declared the state class (`.kc-hidden` → `display: none`) BEFORE the components' own `display: flex` declarations — equal specificity, later declaration wins — so every show/hide state change was correctly computed (the state machine was verified clean against real trusted clicks) and never applied: the list could not hide, ever, in any state. Correct state machine, rotted presentation layer. The redesign therefore also changed the state-hiding mechanism so such a defeat cannot recur: hidden states are `visibility`/`opacity`/`transform` only, class-driven declaratively (with a delayed `visibility` leg, still zero listeners); no `display` flip exists anywhere in the widget anymore.

Redesign decisions (replacement, not re-skin; behavior parity kept — same scan machine, same strings):

- Two shapes anchored at one point (16px in from the bottom-left corner): a compact mood-driven **marker pill** (alert icon + count chip — error tint with findings, calm green on a settled zero verdict, pulsing `…` while the DB resolves; `markerMood` is a named scan-state rule both the marker and the card consume) plus a slim **collapse handle** that anchors the corner and paints above the pill, so collapsing tucks the pill behind it (slide + fade, a red dot marks findings while tucked) — the collapse/expand affordance the owner explicitly kept.
- An **open report card** (not a full-height docked panel): rises from the pill's anchor with a spring, marker row departs at the same beat, header (eyebrow + exact title + count chip + close), finding rows (error roundel, name, 2-line clamped summary, hover-revealed open-affordance arrow), footer affordance hint + `esc` key chip, contained scrolling (`overscroll-behavior`) with theme-standard thin scrollbars, `9+` count cap unchanged.
- Motion lives in CSS declarations keyed to the chrome's classes; the rows' rise replay is bound to the `.kc-open` class itself (animation exists only while the class does), so open, live inserts and re-opens choreograph without a single event listener; first-render entrance for the marker row.
- Keyboard + a11y: the card is `role="dialog"`, opens focused (hand-off via rAF in the owning module), closes on `keydown` inside the shadow root (the injection's event isolation stops key propagation at the shadow root, which is the listening element), hands focus back to the pill on close; the pill carries the exact string via a visually hidden span so the accessible and probe-visible texts agree.
