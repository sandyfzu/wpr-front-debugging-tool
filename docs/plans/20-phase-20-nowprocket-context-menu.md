# P20: `nowprocket` context-menu entry

## TLDR

One page-scoped context-menu entry, **Open ?nowprocket**, opens the clicked document in a new tab with WP Rocket's cache-bypass parameter added when absent. Reuses the existing bypass vocabulary (`CACHE_BYPASS_QUERY_PARAM`, `isCacheBypassUrl` in `lib/wp-rocket/constants.ts`) and adds the one missing transform; one menu registry row plus its click arm. No permissions, storage, messaging, panel or SBS behavior change. Depends on the shipped P2 menu registry/router; independent of the active train (parallel P6G.12–.13/P10/P19). P19's menu refactor must carry the row unchanged as a menu-only command.

## P20A.1 — Firefox toolbar-context fix

Depends: P20A. Size: XS. **Shipped 2026-10-27** (`sandyfzu/p20a1`, + fix round 1: build-time split + Firefox badge = doc 17 F2/F2.1); owner manual check passed 2026-10-27.

- **Bug:** Firefox showed only the two "Open Side By Side…" rows. **Cause:** the Firefox build is MV2; Firefox's `menus.json` `ContextType` gates `"browser_action"` (`max_manifest_version: 2`) and `"action"` (`min_manifest_version: 3`), so `create({contexts:['action']})` (row 3) threw synchronously; the creation loop had no per-row guard → rows 3–6 never created + an unhandled rejection from `void createMenuEntries()`.
- **Fix:** `entrypoints/background/menu-contexts.ts` (pure, background-only so colocated): `platformMenuContext(s)(context, manifestVersion)` — identity on MV3+, `'action'` → `'browser_action'` on MV2, `RangeError` for a non-integer/<2 version; `PlatformMenuContext` picked from `Browser.contextMenus.ContextType` (type-pinned). `buildMenuCreateParams()` branches on build-time `import.meta.env.MANIFEST_VERSION` (= shipped manifest's): MV2 → `platformMenuCreateParams(2)`, MV3 → `menuCreateParams()` untouched, so the MV2 table is dead code in Chromium. Registry unchanged. `createMenuRows(rows, create, runtime)` isolates each row (sync throw → `log.error('Menu entry creation refused', {id, cause})`, the rest still created; `lastError` callback path unchanged); `recreateMenuEntries` `.catch`-logs the whole pass. `@wxt-dev/browser` 0.3.6 `contexts` type already admits `browser_action` — no casts.
