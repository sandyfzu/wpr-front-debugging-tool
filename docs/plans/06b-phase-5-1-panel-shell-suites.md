# Phase 5.1 — Panel shell browser suites

**Depends on:** P4.1, P5. **Effort:** S. **Parallelizable with:** P6 implementation.

## TLDR

Automate the browser-observable part of P5's devtools-panel checklist through the P4.1 harness — panel boot states, tab navigation, deep-links, search interactions — by driving the panel as an extension page (real Chrome devtools attach stays manual).

## Approach

The devtools **attach itself** isn't Playwright-scriptable (headless can't load extensions; attaching the panel requires a real devtools window). The suite therefore drives `panel.html` directly (`chrome-extension://…/panel.html`), which is the identical app shell with the same message/search/hash contracts; real-devtools visuals (first-open experience, panel surface in the browser's devtools chrome) stay manual.

Detections are never injected into the panel's store — a fixture page's real detection output IS the fixture; the helper is harness-only (`no shipped module imports it`) and carries no pure logic needing a colocated unit pin (the shim is a pre-boot string stamp, the relay a send) — its honesty is enforced by the flight itself: the panel can only reach ready state through the real contract path.

**Deviations and corrections (each reproduced before it was fixed):**

1. **The manual share shrank; the harness's grew.** The P5I-era annotation said the devtools-native find relay "stays manual (relay actions require the inspected tab)". With the data path's stamped id, the relay delivery IS harness-drivable — the send replicates the devtools page's exact envelope and payload-tabId scoping over the real wire — so the automated share grew from the store's unit pins alone to the full four-action scoping row; what remains manual is narrower: the DevTools-native Ctrl/Cmd+F interception itself (a real DevTools window's own find bar, owner action).
2. **The retry-leg cause classification is not a browser-tier fact.** The first draft asserted the no-receiver cause text; the tier run reproduced a different in-flight cause (the standalone broadcast failed against the runtime's listener state, not the no-receiver shape). The store's unit tests own per-shape classification; the browser leg now (reproduced again after the change) asserts what is determinate at this tier: the re-flight settles in place (the document realm survives — never the contract-failure full reload) and the error view re-renders with one of the two in-flight causes the store's machine can produce.
3. **The palette run-arm hardened from a timed guess to a decided poll.** The first draft pressed Enter after a fixed 120 ms; the full-tier run reproduced an Enter that landed before the highlight re-arm (the reload flight never fired; nothing crashed — it silently didn't run). Now the suite polls the field's own `aria-activedescendant` until the expected row is the highlight, then presses Enter — the replaced wait was never an assertion, so no pin was weakened; the new row assert is strictly stronger (the same hardening applied to the page-jump loop and the shortcuts-overlay run).
4. **Deviations in the helper, additive:** `openPanelForFixture` gained an options object (`origin?`, `bootHash?`) for the deep-link boot leg — a signature change reviewed across every in-flight call site.
5. **Two files deleted (drift, not deliverables):** `tests/e2e/suites/zz-probe10.spec.ts` and `tests/probe-resettle.test.tsx` — both were in-flight probe scratch pinning the reload-settle leg only as console diagnostics (one also logged instead of asserting); the leg they probed is asserted properly by `panel-palette.spec.ts`'s Reload-action test, so nothing of report was lost by the removal. The vitest tier would also have picked up the unit-tree probe file into `pnpm test`, skewing its ledger.
6. **Header cleanup on the six suites:** the in-flight drafts referenced plan-row numbers inside the spec headers ("row 2's outstanding legs" etc.); the headers now carry the contract's own name (the row map lives here, not in code). No assertion changed for this — comment-only.
7. **No AGENTS.md duty:** no new dependency outside the recorded a11y-engine devDependency (agreed with the deliverable), no manifest change, no gate or structure change — the tier's README ledger and this receipts section are the doc updates.
