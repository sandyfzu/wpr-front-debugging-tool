## Sub-phase structure

**TL;DR:** the phase ships as eight independently implementable, reviewable, and committable sub-phases — each the smallest unit that ends with its gates green (`compile`/`lint`/`format:check`/`test`, plus `build` + `check:budgets` where bundle weight moves) and its checklist. Execution: **P6A → P6A.1 → {P6B ∥ P6C ∥ P6D ∥ P6E ∥ P6F} → P6G → P6.1** (P6A.1 = the XS dispatch seam that removes every shared-file edit from the five page letters — §"Carried by every page letter") ([07b](./07b-phase-6-1-panel-pages-suites.md)) — P6A gates every letter; the five page letters are mutually independent given P6A (except P6G's stated deps on the letters that land the search rows), so they merge conflict-free; **P6.1 closes the phase**, its suite rows re-annotated with their enabling letters as they land (the 06b annotation pattern), inheriting the browser-observable rows. Two deltas against the sketched split, with cause: (1) the shared `headers-view-model.ts` is created in **P6A** — it is pure and consumed by both P6B's headers preview and P6F's page, and creating it inside either page letter would break that mutual independence or duplicate the one declaring site; (2) the Search-integration row splits — its read/filter halves ride the page letters that have matching rows (P6C filters `content`, P6D filters `src`/`href`; on the reference surface only the three resource-list pages ever consumed the protocol) and its highlight-cursor half is **P6G**. ### Panel-page specifics (what the bar leaves to the surface)

A page letter adds **no** token, keyframe, primitive, or edit under `components/ui/`, `assets/css/`, `entrypoints/panel/style.css`, `App.tsx` — the P6A.1 seam already landed what the five letters share; a gap is solved page-locally and listed as a **promotion candidate** in the letter's receipts (P6G decides).

- **Frame.** Every page body is `PageFrame` (P6A.1): root `<section class="fdt-page @container" data-fdt-page={id}>` (the shell's entrance, the bar's `L-1` container — **unpadded**, so page breakpoints read the content-region width — and the focus rule's `[data-fdt-page] h1` target) around a `p-3` `flex-col gap-3` body; `PageHeader` is the only `h1` (title · one-line "what am I looking at" subtitle · right-aligned actions). List pages use the frame's `fill` mode (an at-least-full-height column): header, summary and filter bar stay put, the `VirtualList` carries `PAGE_FILL_SCROLLER` (`min-h-48 flex-1 contain-size` — never re-typed) and is the scroller (bar `L-5`); at short heights the region scrolls, bottom padding kept. Filtered-empty `NoMatches` takes `focusAfter` (search field after `clear-search`, the "All" chip after `show-all`; default the `h1`) so its unmounting buttons never drop focus (bar `K-2`). No `position: fixed` inside a page (the entrance leaves a transform on the root, which would anchor fixed children to it) — floating UI goes through the portaled primitives.
- **Geometry.** Content width = panel width − the ≈ 49 px icon rail (`h-8 w-8` rows + `p-2` + 1 px border; the rail is the nav's only form until P5J); floor 320 px panel ≈ 270 px content (bar `L-2`).
- **Shell-owned states, never re-implemented:** `idle`/`fetching` skeleton, fetch error + Retry, render crash. Page bodies render only on `ready`/`refreshing`; `App.tsx`'s single `Match` keeps them mounted across a soft refresh, so bar `S-2` holds with page-owned signals alone; freshness is the status bar's (no page-level refresh spinner). Filtered-empty = P6A.1's `NoMatches`; external links = `ExternalLink`; motion constants = the three in `classes.ts`.
- **Search.** The resource pages' in-page field and the DevTools search box drive the one P5 search store (P6C's "one query, two inputs" bullet — P6D applies it verbatim).
- **Perf fixture.** Bar `P-3`'s 5,000-row fixture is the one P6C commits; letters with row lists run their `D-7` check on it.
