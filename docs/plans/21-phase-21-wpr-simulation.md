# P21: WP Rocket simulation on sites without the feature

## TLDR

Owner idea (2026-10-21): simulate a WP Rocket optimization on a page where it is off, riding P10's before-parse interception (Chromium `chrome.debugger` + CDP `Fetch`, Firefox `filterResponseData`), then try exclusions on top. Use case: a customer reports a Delay JS problem, Delay JS is off when support visits, no credentials. Not P10's rejected G-3 "simulation fallback" (an approximation _instead of_ interception); P21 rides the interception.

**P21A decided 2026-10-28** ([record](#p21a-decision-record-2026-10-28)): Delay JS first, reproduced byte-for-byte from WP Rocket 3.23.5.1's own passes (live receipt: real plugin Delay pass on the site's Delay-off page = its Delay-on page, minus the generator meta). Simulation = a pre-exclusion step in the one P10 pipeline whose output then composes with exclusions exactly as a real Delay-on page does; an optional `simulate` sibling on the session record; its own extension meta (never a fake `data-wpr-features` token), an authority for detection only once the background verifies it, so simulated Delay never counts as served nor as "WP Rocket present"; per-document no-op where WP Rocket already delays; "Simulated" words on every surface; page CSP reported never bypassed. WP Rocket's runtime script is injected verbatim and sha256-pinned — **how it reaches the page (bundled, site-sourced, or P21 dropped) is owner/legal gate [SG-1](#owner-gates-pending), answered before P21D/P21E**. P21B–P21K + P21.1 below; Defer/Lazyload (P21L/P21M) gated. Gate ids are `SG-n` (simulation gates), distinct from P10's G-1…G-5.

**Depends:** P10 (pipeline seam, overlay, session), P10K (row semantics + PHP parity harness). **Train slot:** before release (owner 2026-10-22) — after P10, closed before P8, gated by P15; exact slot recommended after P12, before P13 ([SG-10](#owner-gates-pending)). Stack: nothing added ([Stack](#stack)). Numbering: planned as P20 on feat/p10, renumbered P21 on 2026-10-22 when develop took P20.

### P21A decision record (2026-10-28)

Plugin anchors are relative to the WP Rocket 3.23.5.1 zip pinned by `lib/exclusion-builder/wp-rocket-parity.fixtures.json` (`header.pluginZipSha256` `e42f4b1a…0e31`). Docker site: WP 7.1.3, PHP 8.4.27, WP Rocket 3.23.5.1, `delay_js=1`, `defer_all_js=1`.

**Q1 — Features and order.**

- Answer: (1) **Delay JS** (owner case, proven); (2) **Defer JS** (pure rewrite, no runtime); (3) **Lazyload images/iframes** with an explicit "no above-the-fold/LCP exclusions" caveat. Preload links: possible but approximate, low support value — not planned. RUCSS-like rendering is P13's owner-gated before-parse TEST MODE (decided at P13C, P13 scope — it would reuse P21F's pre-exclusion hook), not a P21 feature.
- Evidence: `rocket_buffer` priorities — IE extract 1 (`IEConditionalSubscriber.php:51`), Lazyload 18, Minify JS 22, Defer 24/25 (`DeferJS/Subscriber.php:32`), Delay + runtime 26 (`DelayJS/Subscriber.php:49-52`), Elementor 28, IE inject 34, meta generator `PHP_INT_MAX`. **Q2 — Fidelity source and proof.**

- Answer: the extension's forward transform reproduces WP Rocket's PHP passes for the pinned version; the runtime is WP Rocket's own bytes (sha256-pinned). "Same as WP Rocket" = for a served document, the pinned version and the given exclusion inputs (bundled `delay_js_exclusions` list + typed rows), the simulated document equals the plugin's passes byte for byte, **except** the generator meta and `<!-- wpr_* -->` comments, which the simulation never emits (Q5/Q9) — the oracle runs the plugin with `rocket_disable_meta_generator` true, which drops exactly those (`Engine/Support/CommentTrait.php:15-28`, `Meta.php:57`; `HTML::delay_js` ends with `add_meta_comment('delay_js', …)`, `HTML.php:135`) — and, under SG-1 (b) only, the IE fallback script. Proven at two levels: TS transform = real plugin on a fixture table (Q11), and plugin-on-OFF-page = live ON page (docker receipt).
- Delay JS mechanics to mirror: gate `HTML::is_allowed` (`HTML.php:147-162`: not `rocket_bypass()`/`DONOTROCKETOPTIMIZE`/post meta `_rocket_exclude_delay_js`, option on); exclusions merged bundled list (75 rows) → user rows → one-click picks → safe mode → filter `rocket_delay_js_exclusions` → escape `+ ?ver #` (`HTML.php:95-133`); rows matched `#{row}#i` against the whole element, first match wins; xmp/svg masked; IE conditionals extracted (pass 1) so untouched — **new pure work: the shipped `lib/exclusion-builder` has no IE-conditional mask**; non-allowed `type` untouched (so another plugin's own delay type, e.g. a custom `type="…delayed…"`, is left alone exactly as WP Rocket leaves it); `type=`→`data-rocket-type=`, valueless `type` removed, `src=`→`data-rocket-src=` (greedy: the first `…src=` attribute, `data-src` included, `HTML.php:240-247`), `type="text/rocketlazyloadscript"` prefixed (`HTML.php:184-263`); runtime `<script>{lazyload-scripts.min.js}</script>` then IE fallback (476 B, a PHP literal: `HTML::get_ie_fallback`, `HTML.php:171-173`) both after the first `/<head[^>]*>/i` (fallback ends up first), then `move_meta_charset_to_head` (`HTML.php:275-315`; `Subscriber.php:81-120`). No nonce is ever added (`grep nonce DelayJS/` = 0).
- Receipts (docker, 2026-10-28): OFF = `/fdt/?fdt-delay=1&fdt-no-store=1&nowprocket=1`, ON = same without `nowprocket` (`fdt-no-store` writes no cache file but does not stop serving an existing one — the first ON capture was a stored copy: `Last-Modified` header + `cached@` footer, different `<head>`; the receipt uses a fresh live render). `nowprocket` skips only Delay JS + the meta here — Minify/Defer/Lazyload still apply (`docs/local-site-runbook.md:81`; OFF and ON both carry the one `data-rocket-defer`), so OFF→ON isolates Delay. `php -n` (8.1.34) running the real `DelayJS\Subscriber::delay_js` + `add_delay_js_script` inside the real IE extract/inject on OFF: output = ON except the meta line and the `wpr_*` comments (Delay-only rerun 2026-10-28, reproduced by the audit; the earlier Delay+Defer run gave all 11 `<script>` elements byte-identical — Defer's rerun was idempotent). PHP 8.1 harness vs 8.4 site made no difference.
- Known gaps (declared in UI copy, never hidden): per-post exclusion meta, one-click picks, safe mode, filter-added rows (Woo, Termly, Uncode, MinimalistBlogger, RocketLazyLoad, AMP integrations), a remote dynamic list newer than the bundled one (fetch needs the site's license key — `DynamicLists/AbstractAPIClient.php:102-115`), Elementor animation script (`Elementor.php:122-148`, only when `ELEMENTOR_VERSION`), Woo gallery style (`WooCommerceSubscriber.php:527-541`). **Combine JS:** with Delay allowed WP Rocket forces `minify_concatenate_js` off (`DelayJS/Subscriber.php:53` → `maybe_disable_option` `:131-137`), so a Delay-off site serving combined bundles would serve them uncombined with Delay on — the simulation cannot un-combine; detected and stated as a caveat (P21D). **AMP:** WP Rocket never delays AMP endpoints (`ThirdParty/Plugins/Optimization/AMP.php:124`) → the step is the identity there (P21D). Late-pass scripts (> 26) are covered by bundled rows for WP Rocket's own (`lazyLoadOptions`, `wpr-beacon`, `wprRemoveCPCSS`, …); third-party late injectors are not. Extras = **SG-8**.
- Rejected: reimplementing the runtime (loses fidelity on exactly the behavior support debugs); fetching the live remote list (license credentials); fetching the site's own runtime file as the base (only exists with WP Rocket installed, varies per site) — it is the SG-1 refusal path, not the default.

**Q4 — Composition with the P10 session.**

- Answer: simulation is a **pre-exclusion step** of `runExclusionPipeline` (`lib/exclusion-builder/pipeline.ts:265-276`, generic `composeSteps` `:69`): simulate → inline-pass replay → existing Delay/Defer/ALR/Lazyload steps (`EXCLUSION_FEATURES`, `set.ts:91`) → builder marker → simulation marker. The simulated document is what WP Rocket would serve, so the shipped steps act on it as on a real Delay-on page: rows restore per row (counts, approximate/match-all caveats, `data-wpr-fdt-excluded` stamps), Delay disable removes runtime + fallback — no new matching code, one row semantics in the product.
- Correctness oracle (precise assertions in Q11):
  - **O1 (exact, every case):** `pipeline(x, {set, simulate})` minus the simulation marker meta `===` `pipeline(served, set)` byte for byte, where `served` = the plugin's output for `x` with no user rows (P21C table: same sentinel runtime + fallback, `rocket_disable_meta_generator` on, so no `wpr_*` comments). Holds by construction once P21D is exact (both sides then enter the same steps with the same text, and the marker strip is string-exact); it is the meaningful claim: a simulated page behaves under the builder exactly like a real Delay-on page, Delay disable included (`<meta charset>` stays moved — `move_meta_charset_to_head` is one-way; no "equals `x`" claim).
  - **O2 (fidelity bound vs WP Rocket with rows):** `N(pipeline(x, {rows R, simulate}))` `=` `N(plugin(x, R))`, `N` defined in Q11. Divergence allowed only in declared classes (pinned outputs); any other divergence is a builder defect that real Delay-on pages share → fixed in `lib/exclusion-builder` under P10K parity, never a P21-only fork.
- One record, additive: optional `simulate?: { features: SimulatedFeatureId[] }` sibling of `set` on the apply payload (`ExclusionSetPayload`, `lib/messaging/exclusion-session.ts:263`), `ActiveExclusionSession` (`:227`), worker request, document-transform request; optional `simulation` block on the `rewritten` outcome (`{feature, state: 'simulated'|'already-served'|'csp-blocked'|'not-applicable', delayed, runtimeInjected, wpRocketVersion, markerId?, cspLimits?, caveats?}`); optional `stage: 'simulate'` on `over-budget`; typed `runtime-unavailable` outcome (runtime could not be obtained — never a runtime-less simulation). Saved per origin next to `SavedExclusionSet` (`lib/storage/exclusion-sets.ts:29`) = **SG-5** (recommended). Registry `SIMULATED_FEATURES` in new `lib/wp-rocket-simulation/`.
- Lifecycle reuses P10 exactly: Apply carries `{set, simulate}` (gate `lib/exclusion-session/controller.ts:844`); P10 G-5 navigation persistence = every eligible document of the session is simulated until Stop/tab close/extension reload; Reset restores `current.simulate` too and stays held while draft (rows + toggle) = applied; Stop keeps the current document (its runtime keeps running) — banner "Reload to see the page without the simulation."
- Rejected: fields inside `ExclusionSet` (pollutes the stored-form rule, caps, parity table; `parseExclusionSet` requires exactly `rows` + `disable`); a second session/record per tab (one backend `arm` per tab, latest wins — they would race); simulation tokens in the closed builder marker v1 (needs a v2 parser in a spoof-tested reader); byte equality with `plugin(x, R)` (false by construction: restore stamps, builder marker, lossy delay rewrite); one forward pass applying rows while delaying (exact vs WP Rocket, but a second row semantics beside P10's, the Delay restore step skipped and its counts/stamps re-created, and Defer rows (passes 24/25 precede Delay 26) needing their own ordering — revisit only if O2's undeclared divergences prove systemic, owner call then).

**Q5 — Already-active detection.**

- Answer: decided **per document** in the simulate step: if the served text has a generator meta whose `data-wpr-features` contains `wpr_delay_js`, or a Delay footprint **inside a `<script>` element** (opening-tag delayed `type` via `isDelayJSType` or `data-rocket-src`; `RocketLazyLoadScripts` controller in an inline body), the step is the identity with `state: 'already-served'`; rows apply to WP Rocket's real output. The scan uses the tag scanner (`html-scan.ts`) under the Delay mask (xmp/svg), so prose, `<pre>`, comments and attribute text mentioning these names (WP Rocket docs, blogs) never count. Vocabulary from `lib/wp-rocket/constants.ts` (`FEATURE_META_TOKENS` `:336`, `DELAY_JS_CONTROLLER` `:89`); string scan, no DOMParser in the SW. Markup alone suffices when the meta is absent (logged-in, white-label, `rocket_disable_meta_generator`).
- Overlay availability (P21J), in order: (1) the session's `rewritten` outcome for this document (the report the lane counts already read): `simulated`/`csp-blocked` → toggle on and editable (can be turned off or Reset); `already-served` → note; `not-applicable` → AMP note; (2) no session outcome but a `wpr-fdt-simulation` marker the background verifies (Q9; e.g. after Stop) → "Simulated · reload to see the page without it" — an unverified marker falls through to (3); (3) neither → live `page-scan` (`entrypoints/exclusion-overlay.content/exclusions/page-scan.ts:37-44` `PICKABLE_SELECTOR`): Delay footprints → "WP Rocket already delays scripts on this page — exclusions apply to its output."; else toggle available. A simulated page carries Delay footprints, so `page-scan` alone would lock the toggle after Apply — hence it is last.
- Edges: Delay on site-wide but off for this post (post meta) looks "off" — indistinguishable from the page; copy says simulation shows what Delay JS _would_ do. Another plugin's delay type is not a WP Rocket footprint and WP Rocket leaves it untouched → simulation does the same (Q2).
- Rejected: refuse at Apply (wrong grain — later pages of a session differ; dead end, UX-D9); simulate on top (double delay corrupts the page); session-level "exclusions only" switch (redundant).

**Q7 — Per-browser feasibility and CSP (policy = SG-3).**

- Facts: the pipeline does nothing with CSP today (no hits in `lib/exclusion-session`, `lib/exclusion-builder`, `entrypoints/background`); Chromium fulfils with original headers minus framing/cookie/speculation headers (`lib/exclusion-session/chromium/paused-request.ts:70-85`); Firefox rewrites the body in place, headers untouched (`entrypoints/background/stream-filter-backend.ts`). The runtime is **inline**, recreates delayed scripts (copying the original's `nonce`), uses `new Function("event", …)` (needs `'unsafe-eval'`) and `data:text/javascript` script URLs (needs `data:` in the script directive), with its own `securitypolicyviolation` fallback for `script-src-elem` (`sessionStorage.rocketCSPIssue`). CSP3 §3.3: a `<meta http-equiv>` policy is "not applied to content which precedes" it — the runtime sits right after `<head>`, before most metas, so a meta policy binds the runtime's later work, not the runtime element. CDP has `Page.setBypassCSP`, `Fetch.fulfillRequest.responseHeaders`. MDN (`webRequest.onHeadersReceived`): extensions' CSP header values are combined; a conflict between two extensions resolves to the stricter policy; "an extension may remove the original CSP header". BCD: MAIN-world scripting Chrome 95+/Firefox 128+ (below floors 145/150).
- Answer (recommended): inject inline exactly where WP Rocket does; the page's CSP applies to it as it would live (honest). A pure CSP evaluator over header policies (Chromium paused headers; Firefox `responseHeaders` captured in a Firefox-only module) + meta policies with their offset decides: runtime element blocked (inline disallowed by a header policy, or by a meta policy preceding the insertion point) ⇒ `csp-blocked`, step = identity: "This page's Content Security Policy blocks inline scripts — WP Rocket's Delay JS would be blocked the same way."; runtime allowed but some of its work blocked (`'unsafe-eval'` absent, `data:` absent, recreated inline scripts disallowed by a later meta policy) ⇒ `simulated` with `cspLimits` naming each, copy: "This page's Content Security Policy blocks <eval / data: scripts / inline scripts> — WP Rocket's Delay JS hits the same limit live; delayed scripts that need it fail here as they would on the site." (exact reproduction, not a half-working extension feature). Nonce reuse optional (deviation: WP Rocket adds none). Same path on both browsers; Chromium serves a fulfilled copy (neutral security, TTFB includes the pause) — timing tools must label it.
- **Unverified → P21B:** whether page CSP applies to CDP-fulfilled inline scripts as served; to `addScriptToEvaluateOnNewDocument` / MAIN-world injections; whether `chrome.debugger` allows `Page.setBypassCSP`; meta-position semantics on both browsers; whether the delay runtime actually runs on a fulfilled copy (interaction → `data-rocket-status=executed`); Firefox equivalents.
- Rejected: `setBypassCSP`/header removal (the page then runs what the real site blocks); hash added to the header (header surgery per document, merges only tighten across extensions, deviates from WP Rocket); MAIN-world/`addScriptToEvaluateOnNewDocument` runtime as default (timing/frame drift, all-frames guard, static content script costs every page) — fallback only if P21B shows inline unworkable and SG-3 picks it; treating partial blocks as `csp-blocked` (hides the very failure the site would show live).

**Q8 — Performance budgets.**

- Wall time: simulate joins the same `DOCUMENT_TRANSFORM_BUDGET_MS` = 2 000 (`lib/exclusion-session/document-transform.ts:34`; Firefox worker grace `WORKER_GRACE_MS` 250, `transform-worker.ts:32`); one linear scan like existing steps (84 KiB ≈ 1 ms, 4.1 MiB ≈ 270 ms measured for the pipeline); overrun named `stage: 'simulate'`.
- Bytes: every row is at its ceiling (P21A run 2026-10-28, Node 24.21.0): background SW 212.0/212.1 KiB, Firefox background 208.4/208.5, Firefox engine worker 103.2/103.3 (gzip 35.3/35.4), overlay 265.4/265.6 (gzip 89.8/90.0, both builds), isolated 161.0/161.2 (gzip 55.1/55.2), whole build 1628.8/1629. Each slice raises only the rows it moves, measured + reasoned (`scripts/budgets.json`). Runtime 14 554 B raw / 4 432 B gzip-6 (+ 476 B fallback): as an inline TS string it lands in **three** bundles (Chromium SW, Firefox background, Firefox worker — until P15A's split); recommended **one packaged asset** (`?url&no-inline`, precedent: KC seed, `entrypoints/background/known-conflicts.ts:33` + its budget row) fetched once by the background and passed in the transform request = **SG-6**.
- Page overhead: ~15 KiB inline JS per simulated document (same as the real site); untouched tabs pay nothing.

**Q9 — Honest status.**

- Rule cited: **R-1** (`completed-exclusion-builder.md:18`: detection stays honest about what WP Rocket served and adds the builder's in-tab effect), plus UI bar S-3 (state copy), K-5/C-2 (word + glyph, never color alone), W-1/W-2 (words, P15 sweep). UX-D6 (data-first, "no theater" = no fake waits) is not the honesty rule — the brief's citation corrected.
- Why load-bearing (verified): WP Rocket with Delay off → authoritative meta refutes Delay (`lib/detection/feature-meta.ts:147-177`) → card "Inactive" while a delay runtime runs; no meta → footprints read Delay "Active" (`lib/detection/detect-optimizations.ts:76-116`, controller version `2.0.5` read as served); and `applyPresencePropagation` (`lib/detection/run-detection.ts:120-127`, called by both `runDetection` and `entrypoints/isolated.content/data-hub.ts:186`) turns any present row into `wpr.present = true` → cards, strip, report and the toolbar badge (`entrypoints/background/badge.ts:96`, `wprPresent` from `data-hub.ts:454`) would claim WP Rocket on a site without it.
- Answer: extension-owned meta `wpr-fdt-simulation` (`v1 delay_js=simulated id=<32 hex>`, read like `lib/detection/builder-fact.ts`: exactly one meta, `name` + `content` only). Page markup is untrusted (a forged or saved copy of the meta must not hide real Delay JS), so the marker alone is never an authority:
  - **Verified** = the background confirms `id` as one its engine wrote for a simulated document **in this tab**. `id` = 128 random bits per simulated document, drawn by the background, passed in the transform request (the engine stays pure), echoed as the `rewritten` outcome's `simulation.markerId`; the background keeps the tab's last 16 `{markerId, origin}` in `session:simulation-markers` (`lib/storage/simulation-markers.ts`), written before the rewritten document is released, so the page can never ask first (Stop clears the session record, not this; kept across Stop — the stopped document keeps running; dropped on tab close and extension reload). Ask `verifySimulationMarker({markerId}) → {features}` (sender-resolved top frame, `boundedAsk`), sent by the data hub (`entrypoints/isolated.content/data-hub.ts`) only when a well-formed marker exists — other pages pay nothing; unknown id, other tab or origin, no receiver, timeout ⇒ unverified.
  - **Verified ⇒ authority**, inside `runChecks(page, simulation?)` (`run-detection.ts:77` — the one function both callers share, so propagation (always after it) and the badge see the corrected rows): (1) the three checks that read script URLs read them through `servedScriptSrc`, where a delayed script's `data-rocket-src` is its served `src` (on a verified page every delayed script is the simulation's — the step is identity where WP Rocket delays): `detectMinifyJs` (`lib/detection/detect-optimizations.ts:223-234`), `scanLazyloadFootprint` (`:149-167`, both lazyload rows), `detectBeacon`'s URL fallback (`lib/detection/priority-elements.ts:392`); (2) `applySimulationFacts` after the checks, before `applyFeatureMetaAuthority`: per simulated row `present = false`, `version = null`, inventory (`scripts`, `delayedScripts`) kept (precedent: a meta-refuted row keeps its markup as inventory), `simulation: 'simulated'`.
  - **Unverified ⇒ annotation only:** every verdict as served (footprints), `simulation: 'unverified'`.
  - **Precedence:** `applySimulationFacts` skips a row the generator meta declares (no `simulation` field; meta authority then rules) — a really-served feature never reads "Simulated"; a verified simulation never meets a declaring meta (identity there).
  - Rows Delay cannot hide (they read links, ids, text or comments; Delay rewrites only script `type`/`src`): `wpr`, RUCSS, `rocket_cdn` (dns-prefetch links), preconnect, fonts, preload links, CSS bg; `defer_all_js` already reads `data-rocket-src ?? src` (`:129`); `async_css`'s `src` gate sees an empty-text external script either way.
  - `applyBuilderFacts` stays an annotation. Contract (additive): `WprDetections['delay_js'].simulation?: 'simulated' | 'unverified'` (+ guard in `lib/messaging/validate.ts`, beside `parseOptionalBuilder`). Verdicts:

  | ------------------------------------------------- | --------------------- | -------- | ------------------------------------------ | ------------------------------------ | ------------------------------------------------- |
  | Verified · WP Rocket, meta without `wpr_delay_js` | `false`               | `meta`   | meta rules                                 | `true` (meta)                        | Inactive + "Simulated in this tab"                |
  | Verified · WP Rocket, no meta, Minify JS served   | `false`               | absent   | `minify_js` `true` (via `data-rocket-src`) | `true` (Minify JS, cache footer)     | Inactive + modifier                               |

## Risks and mitigations

- **Budgets at ceiling:** every touched row is full. → One runtime copy (SG-6); each slice receipts `pnpm build && pnpm check:budgets` and raises only its rows with a reason; no shared module pulled into an unrelated bundle (check the overlay and isolated rows after detection edits).
- **Misreporting detection (R-1):** simulated footprints could read as served, roll up into "WP Rocket present"/the badge, a refuting meta read "Inactive" while a runtime runs, the rewrite hide sibling rows' script URLs (Minify JS), or a forged marker hide real Delay JS. → Authority only for a background-verified marker; `servedScriptSrc` + simulation pass in `runChecks` before meta authority and propagation; declaring meta wins; never `data-wpr-features`/`wpr_*` comments; tests pin the Q9 table incl. `wpr.present`, badge and forged markers; words on every surface.

- **CSP unknowns:** inline runtime may be blocked, or only its eval/`data:`/recreated scripts; CDP-copy semantics unverified. → P21B probe first; `csp-blocked` and `cspLimits` first-class; SG-3.
- **Fidelity gaps invisible from the page** (post meta, picks, safe mode, filters incl. AMP, remote list, Elementor/Woo, Combine JS): → declared in overlay copy + support report ("bundled exclusion list only"), Combine JS detected as a caveat; SG-8 for extras.
- **Upstream drift:** a WP Rocket release changes the transform or runtime. → sha256 pins + `simulation` header block re-derived by `--ci`, `--compare` weekly; version shown to the user; 3.24 already known (Defer only, SG-9).
- **Licensing:** shipping private/GPL runtime bytes in an UNLICENSED extension; two committed detection fixtures already carry the 2.0.4 runtime. → SG-1 answered before P21D/P21E, with bundle/site-sourced/drop paths; until approved, P21 commits no WP Rocket material (sentinel runtime + fallback, synthetic list rows, hashes only, sentinel bodies in the OFF fixture); existing exposure routed to SG-1; provenance only in `docs/plans/`.
- **Regression of the shipped builder:** pipeline and contracts are shared with P10. → Additive optional fields only; simulate absent ⇒ pipeline output byte-identical (pinned by a test over the existing pipeline fixtures); full P10 e2e suites re-run in P21.1.
