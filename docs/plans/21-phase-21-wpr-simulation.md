# P21: WP Rocket simulation on sites without the feature

## TLDR

Owner idea (2026-10-21): simulate a WP Rocket optimization on a page where it is off, riding P10's before-parse interception (Chromium `chrome.debugger` + CDP `Fetch`, Firefox `filterResponseData`), then try exclusions on top. Use case: a customer reports a Delay JS problem, Delay JS is off when support visits, no credentials. Not P10's rejected G-3 "simulation fallback" (an approximation _instead of_ interception); P21 rides the interception.

**P21A decided 2026-10-28** ([record](#p21a-decision-record-2026-10-28)); **every owner gate decided the same day** ([gates](#owner-gates-decided-2026-10-28)). Scope: Delay JS, then Defer JS (P21L), then Lazyload (P21M), registry open for later features. Delay JS is reproduced byte-for-byte from WP Rocket's own passes (live receipt: real plugin Delay pass on the site's Delay-off page = its Delay-on page, minus the generator meta), for the latest stable WP Rocket and the latest patch of the previous minor (rolling window, P21V; supported today: 3.23.5.1 only, window reading open — [Open (b)](#owner-gates-decided-2026-10-28)). Simulation = a pre-exclusion step in the one P10 pipeline whose output then composes with exclusions exactly as a real Delay-on page does; the Delay lane's switch becomes **As served · Simulated · Disabled**, set from the page's real Delay state; its own extension meta (never a fake `data-wpr-features` token), an authority for detection only once the background verifies it, so simulated Delay never counts as served nor as "WP Rocket present"; identity where WP Rocket already delays; "Simulated" words on every surface; page CSP reported, never bypassed. WP Rocket's runtime is injected verbatim from the packaged asset only (never fetched code); WP Rocket's Delay exclusion list ships bundled per version and is superseded by a fetched, strictly validated latest list (data only — the Known Conflicts seed + live pattern; source settled at P21B-list, owner confirms). Allowed on sites without WP Rocket; admin/login screens warn, never block (owner); logged-in renders allowed (plan). P21B–P21N + P21V + P21.1 below; next startable: [P21B-CSP, P21B-list, P21C, P21E, P14.5D0](#p21b-sub-phases). Gate ids are `SG-n` (simulation gates), distinct from P10's G-1…G-5.

**Depends:** P10 (pipeline seam, overlay, session), P10K (row semantics + PHP parity harness), P14.5D0 (served script URL; plan: before P21I, which reuses its helper). **Train slot:** before release (owner 2026-10-22), closed before P8, gated by P15; alongside P12 — P21I + P21J land after P12 merges, P21K + P21.1 start after it ([SG-10](#owner-gates-decided-2026-10-28)). Stack: nothing added ([Stack](#stack)). Numbering: planned as P20 on feat/p10, renumbered P21 on 2026-10-22 when develop took P20.

**Q2 — Fidelity source and proof.**

- Answer: the extension's forward transform reproduces WP Rocket's PHP passes for each supported version (Q10); the runtime is WP Rocket's own bytes (sha256-pinned). "Same as WP Rocket" = for a served document, the selected version and the given exclusion inputs (the `delay_js_exclusions` list in use — bundled or latest, SG-1 — + typed rows), the simulated document equals the plugin's passes byte for byte, **except** the generator meta and `<!-- wpr_* -->` comments, which the simulation never emits (Q5/Q9) — the oracle runs the plugin with `rocket_disable_meta_generator` true, which drops exactly those (`Engine/Support/CommentTrait.php:15-28`, `Meta.php:57`; `HTML::delay_js` ends with `add_meta_comment('delay_js', …)`, `HTML.php:137`). Proven at two levels: TS transform = real plugin on a fixture table (Q11), and plugin-on-OFF-page = live ON page (docker receipt).
- Delay JS mechanics to mirror: gate `HTML::is_allowed` (`HTML.php:147-162`: not `rocket_bypass()`/`DONOTROCKETOPTIMIZE`/post meta `_rocket_exclude_delay_js`, option on); exclusions merged bundled list (75 rows) → user rows → one-click picks → safe mode → filter `rocket_delay_js_exclusions` → escape `+ ?ver #` (`HTML.php:95-133`); rows matched `#{row}#i` against the whole element, first match wins; xmp/svg masked; IE conditionals extracted (pass 1) so untouched — **new pure work: the shipped `lib/exclusion-builder` has no IE-conditional mask**; non-allowed `type` untouched (so another plugin's own delay type, e.g. a custom `type="…delayed…"`, is left alone exactly as WP Rocket leaves it); `type=`→`data-rocket-type=`, valueless `type` removed, `src=`→`data-rocket-src=` (greedy: the first `…src=` attribute, `data-src` included, `HTML.php:240-247`), `type="text/rocketlazyloadscript"` prefixed (`HTML.php:184-263`); runtime `<script>{lazyload-scripts.min.js}</script>` then IE fallback (476 B, a PHP literal: `HTML::get_ie_fallback`, `HTML.php:171-173`) both after the first `/<head[^>]*>/i` (fallback ends up first), then `move_meta_charset_to_head` (`HTML.php:275-315`; `Subscriber.php:81-120`). No nonce is ever added (`grep nonce DelayJS/` = 0).
- Receipts (docker, 2026-10-28): OFF = `/fdt/?fdt-delay=1&fdt-no-store=1&nowprocket=1`, ON = same without `nowprocket` (`fdt-no-store` writes no cache file but does not stop serving an existing one — the first ON capture was a stored copy: `Last-Modified` header + `cached@` footer, different `<head>`; the receipt uses a fresh live render). `nowprocket` skips only Delay JS + the meta here — Minify/Defer/Lazyload still apply (`docs/local-site-runbook.md:81`; OFF and ON both carry the one `data-rocket-defer`), so OFF→ON isolates Delay. `php -n` (8.1.34) running the real `DelayJS\Subscriber::delay_js` + `add_delay_js_script` inside the real IE extract/inject on OFF: output = ON except the meta line and the `wpr_*` comments (Delay-only rerun 2026-10-28, reproduced by the audit; the earlier Delay+Defer run gave all 11 `<script>` elements byte-identical — Defer's rerun was idempotent). Extras: [after the first stable release](#after-p21) (SG-8).

- Answer: simulation is a **pre-exclusion step** of `runExclusionPipeline` (`lib/exclusion-builder/pipeline.ts:265-276`, generic `composeSteps` `:69`): simulate → inline-pass replay → existing Delay/Defer/ALR/Lazyload steps (`EXCLUSION_FEATURES`, `set.ts:91`) → builder marker → simulation marker. The simulated document is what WP Rocket would serve, so the shipped steps act on it as on a real Delay-on page: rows restore per row (counts, approximate/match-all caveats, `data-wpr-fdt-excluded` stamps) — no new matching code, one row semantics in the product.
- Correctness oracle (precise assertions in Q11):
  - **O1 (exact, every case):** `pipeline(x, {set, simulate})` minus the simulation marker meta `===` `pipeline(served, set)` byte for byte, where `served` = the plugin's output for `x` with no user rows (P21C table: same sentinel runtime + fallback, `rocket_disable_meta_generator` on, so no `wpr_*` comments). Holds by construction once P21D is exact (both sides then enter the same steps with the same text, and the marker strip is string-exact); it is the meaningful claim: a simulated page behaves under the builder exactly like a real Delay-on page. `set` never carries `disable.delayJs` together with `simulate` (Q6 mapping), so O1's matrix has no Delay-disable arm on the simulated side; the disable arm is O1 over a real Delay-on input (`<meta charset>` stays moved — `move_meta_charset_to_head` is one-way; no "equals `x`" claim).
  - **O2 (fidelity bound vs WP Rocket with rows):** `N(pipeline(x, {rows R, simulate}))` `=` `N(plugin(x, R))`, `N` defined in Q11. Divergence allowed only in declared classes (pinned outputs); any other divergence is a builder defect that real Delay-on pages share → fixed in `lib/exclusion-builder` under P10K parity, never a P21-only fork.
- One record, additive: optional `simulate?: { features: SimulatedFeatureId[] }` sibling of `set` on the apply payload (`ExclusionSetPayload`, `lib/messaging/exclusion-session.ts:263`), `ActiveExclusionSession` (`:227`), worker request, document-transform request; optional `simulation` block on the `rewritten` outcome (`{feature, state: 'simulated'|'already-served'|'csp-blocked'|'not-applicable', delayed, runtimeInjected, wpRocketVersion, siteVersion?, listSource: 'latest'|'bundled', listFetchedAt?, listMiss?, markerId?, cspLimits?, caveats?}` — field types in P21E); optional `stage: 'simulate'` on `over-budget`; typed `runtime-unavailable` outcome with a `cause` (the packaged asset could not be loaded or verified — never a runtime-less simulation). **Q5 — Already-active detection.**

- Answer: decided **per document** in the simulate step: if the served text has a generator meta whose `data-wpr-features` contains `wpr_delay_js`, or a Delay footprint **inside a `<script>` element** (opening-tag delayed `type` via `isDelayJSType` or `data-rocket-src`; `RocketLazyLoadScripts` controller in an inline body), the step is the identity with `state: 'already-served'`; rows apply to WP Rocket's real output. The scan uses the tag scanner (`html-scan.ts`) under the Delay mask (xmp/svg), so prose, `<pre>`, comments and attribute text mentioning these names (WP Rocket docs, blogs) never count. Vocabulary from `lib/wp-rocket/constants.ts` (`FEATURE_META_TOKENS` `:336`, `DELAY_JS_CONTROLLER` `:89`); string scan, no DOMParser in the SW. Markup alone suffices when the meta is absent (logged-in, white-label, `rocket_disable_meta_generator`).
- The page's **real Delay state** for the overlay (P21J), existing evidence only, in order: (1) the session's `rewritten` outcome for this document (the report the lane counts already read): `simulated`/`csp-blocked` → not delayed by WP Rocket (mode Simulated applied); `already-served` → delayed; `not-applicable` → AMP; the builder's own Delay disable fact (session record / builder marker `delay_js=off`) → delayed (mode Disabled applied); (2) no session outcome but a `wpr-fdt-simulation` marker the background verifies (Q9; e.g. after Stop) → not delayed, "Simulated · reload to see the page without it" — an unverified marker falls through to (3); (3) neither → the live document: root `<html>` carries `amp` or `⚡` → AMP (before any Apply too; the attribute list has one declaring site, `lib/wp-rocket-simulation/amp.ts`, shared with P21D's text check); else `page-scan` (`entrypoints/exclusion-overlay.content/exclusions/page-scan.ts:37-44` `PICKABLE_SELECTOR`): Delay footprints → delayed; else not delayed. A simulated page carries Delay footprints and a Delay-disabled page carries none, so `page-scan` alone would misread both after Apply — hence it is last.
- Edges: Delay on site-wide but off for this post (post meta) looks "off" — indistinguishable from the page; copy says simulation shows what Delay JS _would_ do. Another plugin's delay type is not a WP Rocket footprint and WP Rocket leaves it untouched → simulation does the same (Q2).
- Rejected: refuse at Apply (wrong grain — later pages of a session differ; dead end, UX-D9); simulate on top (double delay corrupts the page); session-level "exclusions only" switch (redundant).

**Q6 — Placement (SG-2 decided).**

- Answer: the Delay JS lane's "Disable feature" switch (`entrypoints/exclusion-overlay.content/exclusions/lane.tsx:409-425`) becomes **one 3-option segmented control: As served · Simulated · Disabled** (Delay lane only; the Defer and ALR lanes keep their switch until their simulation phase — Defer in P21L). One Apply/Reset baseline for mode + rows. Availability from the real Delay state (Q5):
  - delayed by WP Rocket → As served (start) and Disabled available; Simulated unavailable — "WP Rocket already delays scripts on this page — exclusions apply to its output.";
  - not delayed → As served (start) and Simulated available; Disabled unavailable — "WP Rocket doesn't delay scripts on this page — nothing to disable.";
  - AMP (tier 1 `not-applicable`, or tier 3's root attribute) → As served only — "WP Rocket never delays AMP pages.".
  - Rows apply under As served (to WP Rocket's real delay) and Simulated (to the simulated delay); unused under Disabled (today's behavior). After Apply under Simulated the lane reads "N delayed by the simulation · M excluded by your rows" and its "On this page" list fills from `page-scan` (picking unchanged).
- Contract mapping (pure, one function each way, no contradictory state): As served ⇔ `disable.delayJs = false`, no `delay_js` in `simulate`; Simulated ⇔ `disable.delayJs = false` + `simulate.features` ∋ `delay_js`; Disabled ⇔ `disable.delayJs = true`, no `delay_js` in `simulate`. `ExclusionSetToggles` (`lib/exclusion-builder/set.ts:66`) unchanged. `disable.delayJs` + `simulate` ∋ `delay_js` together: the apply-payload parser rejects it (`'reject'`); a stored saved set carrying both reads as Disabled (simulate dropped, logged — `'ignore'` tolerance). A saved/applied mode that is unavailable on the current page (e.g. Simulated saved, page now delayed) opens as As served with the lane note; the engine stays per-document safe either way (Q5 identity).
- Indicator words: drafted in P21I/P21K, owner approves at P21K.
- Discoverable where the agent already looks (context menu, panel status entry, palette open the builder).
- Rejected: a separate "Simulate" toggle beside the disable switch (two controls for one feature state; the contradictory pair would need its own rule); a new mode row in `modes.ts` (splits one Apply across panels; cross-mode draft composition is new machinery; the slot is kept for P13/P14 testers); popup (URL-switch contract, closes on blur, deferred to P8); panel (P10 G-1 amendment removed it as a builder surface — status only).

**Q7 — Per-browser feasibility and CSP (SG-3 decided).**

- Facts: the pipeline does nothing with CSP today (no hits in `lib/exclusion-session`, `lib/exclusion-builder`, `entrypoints/background`); Chromium fulfils with original headers minus framing/cookie/speculation headers (`lib/exclusion-session/chromium/paused-request.ts:70-85`); Firefox rewrites the body in place, headers untouched (`entrypoints/background/stream-filter-backend.ts`). The runtime is **inline**, recreates delayed scripts (copying the original's `nonce`), uses `new Function("event", …)` (needs `'unsafe-eval'`) and `data:text/javascript` script URLs (needs `data:` in the script directive), with its own `securitypolicyviolation` fallback for `script-src-elem` (`sessionStorage.rocketCSPIssue`). CSP3 §3.3: a `<meta http-equiv>` policy is "not applied to content which precedes" it — the runtime sits right after `<head>`, before most metas, so a meta policy binds the runtime's later work, not the runtime element. CDP has `Page.setBypassCSP`, `Fetch.fulfillRequest.responseHeaders`. MDN (`webRequest.onHeadersReceived`): extensions' CSP header values are combined; a conflict between two extensions resolves to the stricter policy; "an extension may remove the original CSP header". BCD: MAIN-world scripting Chrome 95+/Firefox 128+ (below floors 145/150).
- Answer (owner: "do what WP Rocket does" — this is it): inject inline exactly where WP Rocket does; never bypass; the page's CSP applies as it would live. The only addition is naming the cause. A pure CSP evaluator over header policies (Chromium paused headers; Firefox `responseHeaders` captured in a Firefox-only module) + meta policies with their offset decides: runtime element blocked (inline disallowed by a header policy, or by a meta policy preceding the insertion point) ⇒ `csp-blocked`, step = identity: "This page's Content Security Policy blocks inline scripts — WP Rocket's Delay JS would be blocked the same way."; runtime allowed but some of its work blocked (`'unsafe-eval'` absent, `data:` absent, recreated inline scripts disallowed by a later meta policy) ⇒ `simulated` with `cspLimits` naming each, copy: "This page's Content Security Policy blocks <eval / data: scripts / inline scripts> — WP Rocket's Delay JS hits the same limit live; delayed scripts that need it fail here as they would on the site." (exact reproduction, not a half-working extension feature). **No nonce reuse** (WP Rocket adds none). Same path on both browsers; Chromium serves a fulfilled copy (neutral security, TTFB includes the pause) — timing tools must label it.
- **Unverified → P21B-CSP:** whether page CSP applies to CDP-fulfilled inline scripts as served; to `addScriptToEvaluateOnNewDocument` / MAIN-world injections; whether `chrome.debugger` allows `Page.setBypassCSP`; meta-position semantics on both browsers; whether the delay runtime actually runs on a fulfilled copy (interaction → `data-rocket-status=executed`); Firefox equivalents.
- Rejected: `setBypassCSP`/header removal (the page then runs what the real site blocks); hash added to the header (header surgery per document, merges only tighten across extensions, deviates from WP Rocket); nonce reuse (deviates from WP Rocket); MAIN-world/`addScriptToEvaluateOnNewDocument` runtime (timing/frame drift, all-frames guard, static content script costs every page) — only if P21B-CSP proves inline unworkable, and then back to the owner; treating partial blocks as `csp-blocked` (hides the very failure the site would show live).

- Bytes: every row was at its ceiling on `develop` (P21A run 2026-10-28, Node 24.21.0): background SW 212.0/212.1 KiB, Firefox background 208.4/208.5, Firefox engine worker 103.2/103.3 (gzip 35.3/35.4), overlay 265.4/265.6 (gzip 89.8/90.0, both builds), isolated 161.0/161.2 (gzip 55.1/55.2), whole build 1628.8/1629. P12 raises background → 213.2, isolated → 165.3/56.6, Firefox background → 209.6, whole build → 1635.4 (P12 branch, not yet on `develop`): every slice re-measures on the tree it lands on (after P12 merges for I, K, P21.1). Each slice raises only the rows it moves, measured + reasoned (`scripts/budgets.json`). Runtime 14 554 B raw / 4 432 B gzip-6 (+ 476 B fallback + the bundled list rows): **one packaged asset** (SG-6 decided) loaded once by the background and passed in the transform request — never an inline string (it would land in three bundles: Chromium SW, Firefox background, Firefox worker). Shipped as a `public/` file, not a `?url&no-inline` import: WXT names every asset of the single-entry background build `assets/background.[ext]` (`node_modules/wxt/dist/internal/builders/vite/index.mjs:166-168`, WXT 0.21.5), the name the KC seed already owns with its exact budget row (`scripts/budgets.json` "known-conflicts DB seed asset (background-owned)", glob `assets/background.json`) — a second JSON import would be renamed by emission order and silently swap what the row measures (P21G). The whole-build backstop row globs JS only, so the data file is measured by its own rows.
- Page overhead: ~15 KiB inline JS per simulated document (same as the real site); untouched tabs pay nothing.

**Q9 — Honest status.**

- Rule cited: **R-1** (`completed-exclusion-builder.md:18`: detection stays honest about what WP Rocket served and adds the builder's in-tab effect), plus UI bar S-3 (state copy), K-5/C-2 (word + glyph, never color alone), W-1/W-2 (words, P15 sweep). UX-D6 (data-first, "no theater" = no fake waits) is not the honesty rule — the brief's citation corrected.
- Why load-bearing (verified): WP Rocket with Delay off → authoritative meta refutes Delay (`lib/detection/feature-meta.ts:147-177`) → card "Inactive" while a delay runtime runs; no meta → footprints read Delay "Active" (`lib/detection/detect-optimizations.ts:76-116`, controller version `2.0.5` read as served); and `applyPresencePropagation` (`lib/detection/run-detection.ts:120-127`, called by both `runDetection` and `entrypoints/isolated.content/data-hub.ts:186`) turns any present row into `wpr.present = true` → cards, detection widget, report and the toolbar badge (`entrypoints/background/badge.ts:96`, `wprPresent` from `data-hub.ts:454`) would claim WP Rocket on a site without it.
- Answer: extension-owned meta `wpr-fdt-simulation` (`v1 delay_js=simulated id=<32 hex>`, read like `lib/detection/builder-fact.ts`: exactly one meta, `name` + `content` only). Page markup is untrusted (a forged or saved copy of the meta must not hide real Delay JS), so the marker alone is never an authority:
  - **Verified** = the background confirms `id` as one its engine wrote for a simulated document **in this tab**. `id` = 128 random bits per simulated document, drawn by the background, passed in the transform request (the engine stays pure), echoed as the `rewritten` outcome's `simulation.markerId`; the background keeps the tab's last 16 `{markerId, origin}` in `session:simulation-markers` (`lib/storage/simulation-markers.ts`), written before the rewritten document is released, so the page can never ask first (Stop clears the session record, not this; kept across Stop — the stopped document keeps running — and across a plain worker restart; dropped on tab close beside `controller.tabClosed`, and on extension update/reload in the `runtime.onInstalled` (`reason: 'update'`) handler that already calls `controller.resetAll()` (`entrypoints/background/exclusion-sessions.ts:246-252`), because `session:` storage may survive a reload (`lib/storage/exclusion-sessions.ts:18-21`); browser shutdown clears the area itself). Ask `verifySimulationMarker({markerId}) → {features}` (sender-resolved top frame, `boundedAsk`), sent by the data hub (`entrypoints/isolated.content/data-hub.ts`) only when a well-formed marker exists — other pages pay nothing; unknown id, other tab or origin, no receiver, timeout ⇒ unverified.
  - **Verified ⇒ authority**, inside `runChecks(page, simulation?)` (`run-detection.ts:77` — the one function both callers share, so propagation (always after it) and the badge see the corrected rows): `applySimulationFacts` after the checks, before `applyFeatureMetaAuthority`: per simulated row `present = false`, `version = null`, inventory (`scripts`, `delayedScripts`) kept (precedent: a meta-refuted row keeps its markup as inventory), `simulation: 'simulated'`. Sibling rows that read script URLs (`detectMinifyJs`, both lazyload rows, `detectBeacon`'s URL fallback) already read the served URL through `servedScriptSrc` on every page — P14.5D0, the pre-release fix of the same blind spot on real Delay-on pages without a declaring meta.
  - **Unverified ⇒ annotation only:** every verdict as served (footprints), `simulation: 'unverified'`.
  - **Precedence:** `applySimulationFacts` skips a row the generator meta declares (no `simulation` field; meta authority then rules) — a really-served feature never reads "Simulated"; a verified simulation never meets a declaring meta (identity there).
  - Rows Delay cannot hide (they read links, ids, text or comments; Delay rewrites only script `type`/`src`): `wpr`, RUCSS, `rocket_cdn` (dns-prefetch links), preconnect, fonts, preload links, CSS bg; `defer_all_js` already reads `data-rocket-src ?? src` (`:129`); `async_css`'s `src` gate sees an empty-text external script either way.
  - `applyBuilderFacts` stays an annotation. Contract (additive): `WprDetections['delay_js'].simulation?: 'simulated' | 'unverified'` (+ guard in `lib/messaging/validate.ts`, beside `parseOptionalBuilder`). Verdicts:

## Risks and mitigations

- **Budgets at ceiling:** every touched row is full, and P12 moves the shared rows. → One packaged data file (SG-6); each slice receipts `pnpm build && pnpm check:budgets` on the tree it lands on and raises only its rows with a reason; no shared module pulled into an unrelated bundle (check the overlay and isolated rows after detection edits).
- **Misreporting detection (R-1):** simulated footprints could read as served, roll up into "WP Rocket present"/the badge, a refuting meta read "Inactive" while a runtime runs, the rewrite hide sibling rows' script URLs (Minify JS), or a forged marker hide real Delay JS. → Authority only for a background-verified marker; simulation pass in `runChecks` before meta authority and propagation; `servedScriptSrc` on every page (P14.5D0); declaring meta wins; never `data-wpr-features`/`wpr_*` comments; tests pin the Q9 table incl. `wpr.present`, badge and forged markers; words on every surface.
- **Wrong Delay control state after Apply:** a simulated page looks Delay-served to `page-scan`, a Delay-disabled one looks Delay-free. → Real state reads the session outcome, the builder's disable fact and the verified marker first (Q5).
- **Simulating a page WP Rocket never optimizes** (admin/login screens): → inline warning (SG-4), never a block.
- **Persisted mode forgotten:** an origin's saved mode could rewrite pages unnoticed. → Restore never arms; every simulated load shows the overlay indicator + widget/panel words (SG-5).
- **CSP unknowns:** inline runtime may be blocked, or only its eval/`data:`/recreated scripts; CDP-copy semantics unverified. → P21B-CSP probe first; `csp-blocked` and `cspLimits` first-class.
- **Fetched latest list (remote JSON):** malformed, oversize, slow, hostile, or the endpoint's unauthenticated access withdrawn. → Data only (never evaluated), text read with a size cap, `JSON.parse`, strict shape/count/length validation, rows compiled like user rows; last valid copy, else the pinned bundled list, the miss named; periodic background fetch, never on the Apply path; source confirmed by the owner after P21B (P21N).
- **Bundled runtime staleness:** a new WP Rocket runtime ships before the bump PR. → Weekly workflow warning on unpinned window versions (Q10); the overlay names the simulated WP Rocket version.
- **Asset name collision:** a second background `?url` JSON import would share the KC seed's `assets/background.json` name and budget row. → The data ships from `public/` at a fixed path; budget rows required to match exactly one file (P21G).
- **Fidelity gaps invisible from the page** (post meta, picks, safe mode, filters incl. AMP, a site's own list copy, variant/older runtimes, Elementor/Woo, Combine JS): → declared in overlay copy + support report (list source named), Combine JS detected as a caveat; extras after the first stable release (SG-8).
- **Upstream drift:** a WP Rocket release changes the transform, runtime or a builder rule. → Version registry + sha256 pins per supported version, re-derived by `--ci`, `--compare` and new-release warnings weekly; version shown to the user; 3.24's one difference already known (P21V).

- **Firefox double carry:** the engine still ships in the Firefox background (P15A). → The SG-6 asset avoids tripling the runtime; Firefox-only code (header capture) in separate modules.
