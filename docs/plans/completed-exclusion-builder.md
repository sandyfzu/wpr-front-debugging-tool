# Exclusion Builder: shipped P10 and open items

## TLDR

P10 shipped on `feat/p10` (2026-10-20 → 2026-10-27) and **closed 2026-10-27**: owner Chrome live checks passed (2026-10-21, 2026-10-26), owner Firefox check passed (2026-10-27, [script](#owner-firefox-check-script)). The builder is a shadow-isolated **overlay injected into the inspected page**: the user picks scripts/elements, composes exclusions, clicks **Apply**; the tab reloads and the extension **rewrites the served HTML before parse** (Chromium `debugger` + CDP `Fetch`; Firefox `webRequest.filterResponseData` + engine Web Worker). Rows mean what they mean on the live site: WP Rocket's stored form and runtime matching are mirrored (369-row PHP-derived parity table — 282 match + 87 save —, informational CI job). Panel cards and the on-page strip show the builder's in-tab effect on top of what WP Rocket served.

Merged into `develop` 2026-10-27 (`515691d`), so P19 and P21 can build on it. Open items are owned elsewhere ([follow-ups](#follow-ups-owners)). This record replaces the implementation plan; sub-phase instructions, receipts and audit rounds stay in Git history. Code, lockfile, `scripts/budgets.json` and the runbooks override the historical numbers below.

Superseded (do not reintroduce): the separate unlisted builder page + file pick/rewrite + Chrome overrides flow (no `exclusion-builder.html` was ever built in this port); the panel palette's "Open Exclusion Builder" row; any simulation fallback.

## Architecture facts

Layout: `lib/exclusion-builder/` (pure engine), `lib/exclusion-session/` (backend-agnostic session core + both backends' pure parts), `lib/messaging/exclusion-session.ts` / `exclusion-panel.ts`, `lib/storage/exclusion-{sets,sessions}.ts`, `entrypoints/exclusion-overlay.content/`, `entrypoints/exclusion-transform-worker.ts` (Firefox only), background wiring rows. AGENTS.md has the runbook.

### Session core

- **Seam:** a backend implements `arm(tabId, generation, origin?)` / `disarm` / `resume` (wake re-validation, awaits no host call); per tab the latest of arm/resume/disarm wins; a timed-out arm or resume is always followed by a disarm. Generation = session `startedAt` (per-controller, strictly increasing even with a backward clock), so a replaced session's late document/end is dropped.
- **Eligibility** (`isRewritableResponse`): MIME essence exactly `text/html` (missing type and XHTML not rewritten), status 200–599 minus 3xx/204/205/206/304, not `HEAD`; ineligible ⇒ passed through unrecorded. Origin gate: only documents of the applied origin are rewritten.
- **Document step:** 8 MiB body cap (`body-unavailable`) → decode → engine → re-encode; any failure serves the original bytes. Budget **2 000 ms** (`DOCUMENT_TRANSFORM_BUDGET_MS`; measured 2026-10-20: 84 KiB ≈ 1 ms, 844 KiB ≈ 14 ms, 4.1 MiB ≈ 270 ms). Chromium: an MV3 service worker has **no `Worker`** (verified CFT 156) ⇒ in-process runner checked after each step — detects (`over-budget` naming feature, and row when unambiguous), cannot preempt; a slow match blocks the background for all tabs until it returns. Firefox: the MV2 background page has `Worker` ⇒ preempting runner (killed at budget + 250 ms).
- **Charset:** BOM › `Content-Type` charset › 1 024-byte `<meta>` prescan › default; re-encode **in the original encoding, never transcode** (transcoding would change charset-less subresource decoding; Firefox cannot rewrite the header from a stream). UTF-8, UTF-16LE/BE, all 29 single-byte encodings; multi-byte CJK and `replacement` ⇒ `decode-failed`; unencodable rewrite ⇒ `encode-failed`; fatal decode, BOM kept; unchanged runs serve original bytes.
- **State:** the `session:` record per tab is the state, read fresh per event; it is a **hint** re-validated on wake (stale ⇒ cleared, served unmodified). `session:` survives SW/event-page suspension, is cleared on browser restart; Chromium also clears it on extension reload/update (docs); Firefox temporary reload fires `onInstalled {reason: 'update'}` **and** clears it (verified); `onInstalled` `update` ends every session anyway. Content scripts never read records (they ask the background).
- **Bounds:** ≤ 500 rows/feature, ≤ 2 048 chars/row, ≤ 64 Ki chars/set; `local:exclusion-sets` ≤ 4 MiB LRU; ≤ 8 active sessions (`session-limit`, never evicting) + ≤ 32 warnings; active record ≤ 512 KiB. Ask worst cases (apply 11.85 s, stop 4.25 s, status 2 s) stay < 90 % of the sender deadlines; prevalidation is work-bounded (5.78 M units ⇒ `PREVALIDATION_CPU_BOUND_MS` 1 600).
- **Regex guard** (`regex-risk.ts`, Delay/Defer only): rejects nested ambiguous repetition, overlapping looped alternation, back-references in loops, too-complex rows — deterministic, never throws. Heuristic: polynomial shapes pass (measured Node 24: `.*jquery` vs 100 KiB inline script 4.4 s; `\s*\s*$` on 4 KiB 11.6 s). Known false positive `(?:[^"]|\\")*`. Dependencies rejected (`safe-regex*` wrong verdicts, `redos-detector` ~800 KB, `recheck` ~5.8 MB) vs ~9 KB in-repo.
- **Served identity** (in the record): `urlPath` (origin + path) + `urlDigest` (SHA-256 of the URL without fragment — no raw query stored; low-entropy queries are guessable), monotonic `order` (a restarted background never drops later documents), arrival wall time `receivedAt`, `copy`, `serviceWorkersBypassed`, speculation-rules flags. A late or abandoned response records `failed{not-served}` with its own identity, never over a later page.

### Chromium backend (CDP)

- Session commands: attach `1.3` → `Fetch.enable` (`*`, Document, Response stage) → `Network.enable` (zero buffers) → `Network.setBypassServiceWorker` (needs `Network` enabled; the tab's service workers are bypassed for every request during a session — tab-wide, no per-origin scope) → `Page.enable` → speculation-rules guard (fresh attach) → page target. Top frame = page target id (equals the main-frame `frameId`; iframe documents differ).
- **Multi-client CDP:** attach succeeds with DevTools already open (CFT 156 and stable Chrome 155.0.8059.86) and with Playwright driving the browser; another extension's `Fetch` interception chains with ours. UI cost seen in the owner's headed run: the auto-opened native DevTools window closed moments after the attach. "Another debugger is already attached" is this extension's own session ⇒ detach + attach afresh.
- `chrome.debugger.detach()` fires no `onDetach`; a renderer crash fires none either. Error/detach map (strings from Chromium source): `chrome://`, extension, web store, file URLs ⇒ `unsupported-page`; "Cannot attach to this target." (what `DeveloperToolsAvailability` answers) and policy strings ⇒ `debugging-policy`; `canceled_by_user` ⇒ `infobar-cancelled`; `target_closed` + tab gone ⇒ nothing, + non-http(s) ⇒ `unsupported-page`, + still web ⇒ `detached`.
- **Fulfilled documents are copies** (`Fetch.fulfillRequest`): `neutral` security, no cert, empty `nextHopProtocol`, zero connect/TLS timings, TTFB includes the pause (matters for P11–P14 timing tools). So bytes are fulfilled **only when the exclusions changed the document**; otherwise `Fetch.continueResponse` keeps the real response (still `secure`/h2). Fulfil drops `content-encoding`/`content-length`/`transfer-encoding`/`set-cookie` (Chromium already stripped cookies before the pause). 304 revalidations pause as 200 with the body.
- **Speculation rules:** WordPress ≥ 6.8 prefetches on pointerdown and a prefetched navigation never pauses in `Fetch` ⇒ every session document drops `<script type=speculationrules>` (also delayed ones), the `Speculation-Rules` header is removed, and a silent origin-scoped page-world guard (`Page.addScriptToEvaluateOnNewDocument`, needs `Page.enable`) removes script-inserted rules. A hostile page can disable the guard for itself only.
- **Chromium `scripting.executeScript` argument serialization drops null-valued keys** (CFT 156): readers treat absent as null.

### Firefox backend (stream filter)

The Firefox build is **MV2 with a persistent background page** (no suspension; state lost only on browser restart or extension reload/update). Permissions `webRequest` + `webRequestBlocking` (MV3 would also need `webRequestFilterResponse`). Facts verified on Firefox 158 (used by the design):

- Match patterns with an explicit **port never match** (webRequest, content scripts, `tabs`, `permissions`); the repo's port-less `URL_PATTERNS` are safe; any composed pattern must strip the port.
- A **synchronous in-memory armed table** gates blocking `onBeforeRequest` (a fresh background has none ⇒ every stored session is stale). `filterResponseData` also works after an `await`, but the table is kept.
- A blocking `onHeadersReceived` precedes `onstart` (a non-blocking one arrived ~200 ms after `onstop`); facts are last-write-wins and only a final status decides (a revalidation reports `304` then the cached `200`).
- Bodies arrive decoded (no header fix-up needed); a 3xx's filter fails `Invalid request ID` and `onBeforeRequest` re-fires with the same id; `disconnect()` before `onstart` throws.
- Truncation: the body is rewritten only after the request completed (`onCompleted`, or a 1 s settle fallback); `onErrorOccurred` can arrive ~25 ms after `onstop`. A truncated **compressed** body reports completion and is undetectable (residual).
- Firefox sets `runtime.lastError` to `null` on success (`utils/last-error`); Firefox ignores `composed: false` on constructed `KeyboardEvent`s (the key guard sends plain `Event` copies).
- Divergence vs CDP: leaving http(s) does not end a Firefox session (next http(s) document is still rewritten); Firefox records are never copies (`copy: false`, in-place rewrite); no `Speculation-Rules` header support.
- The DevTools panel has no `tabs` API and gets no content-script `runtime.sendMessage` ⇒ panel→tab asks go through a background relay (`relayTabAsk`, gate `isOwnExtensionPageSender`: tab-less, own id, own-page URL compared by scheme + host) and the page's three pushes through a `tab-pushes` port whose background listeners exist only while subscribed (a boot-time handler would turn Chromium's no-receiver rejections into resolved sends). Chromium never relays. Panel sender shape: `envType: 'devtools_child'`, `moz-extension://…/panel.html`, no `tab`.

### Overlay

- **Runtime content script** (`registration: 'runtime'`) injected into frame 0 by `scripting.executeScript` (`scripting` permission, no install warning, both builds): WXT bundles content scripts as IIFE so a dynamic `import()` is inlined; a web-accessible module would expose the code to every page. The overlay costs untouched pages nothing.
- **Re-open:** on `tabs.onUpdated` `complete` for an active session of the page's origin; not `document_start`: without `webNavigation` (install warning "Read your browsing history") nothing targets the new document's commit. One overlay per document via an isolated-world slot claim (racing opens inject once; spoofed page elements ignored); fold/close memory in `session:` per tab.
- **Isolation:** one shadow root, everything in a `popover="manual"` top layer (above any page z-index/transform; page CSS zoom undone; px, not rem); a page modal ⇒ paused pill. Events stop at the shadow root and Solid delegates there — WP Rocket's Delay JS runtime saves first interactions at `window` and replays them on `composedPath()[0]` (a toggle clicked twice; also the root cause of the old side-by-side flake). Key/input/clipboard events through the host are stopped at the window by `components/injected-ui/key-guard.ts`, installed first by the isolated content script.
- **Page verdict** ("Applied" / "not intercepted" / "can't verify"): compares the record's digest + arrival time with the page's wall-anchored navigation start (`Date.now() − performance.now()`, recorded once at `document_start` by the isolated content script; `executeScript` shares that world in both browsers — page main world sees nothing). `performance` clocks stop during OS sleep on non-Windows and wall clocks drift, hence the anchor. A history move ⇒ "can't tell"; a bfcache restore (bfcache does engage on session tabs) reads "can't verify".
- **Editor:** one input per row (multi-line paste splits like the textarea: CR, LF, CRLF all break lines), virtualized lanes, click-to-pick + keyboard "On this page" list, autosave via `saveExclusionSet`, time-sliced long pastes (no task ≥ 50 ms), Stop ends the session **without reloading** (the rewritten page + draft stay; next load is served normally). Copy-all: async clipboard, else selection copy (content scripts on `http:` pages have no `navigator.clipboard`). Setting a left row's value resets Chromium's native undo (overlay keeps its own Undo).
- **Mode registry** (`modes.ts`): Exclusions is the only row; P13/P14 tester modes plug into the same shell/session/pipeline seam; no mode switch until a second row exists.

### Cross-surface sync (P10N)

- Cause found live: WP Rocket's generator meta keeps every feature-wide/page-off row "Active" though the rewritten page no longer runs it. Option D chosen: an in-band document marker decides the per-row modifier; existing session pushes keep the panel status entry's tab state. Rejected: out-of-band join (wrong after Stop — no reload, page still rewritten), per-element stamps only (disabled vs all-matched indistinguishable), rewriting the meta (misreports what WP Rocket served).
- **Marker:** `<meta name="wpr-fdt-exclusion-builder" content="v1 …">`, tokens in `EXCLUSION_FEATURES` order: `delay_js=off|excluded:<n>`, `defer_all_js=off|page-off|excluded:<n>`, `automatic_lazy_rendering=off|excluded:<n>`, `lazyload=excluded:<n>` (n 1–9999, clamped). Write: last pipeline step removes every copy and appends one at the end of `<head>` (never ahead of a `<meta charset>` prescan) when something changed. Read (amended 2026-10-26): exactly one meta with exactly `name` + `content` that parses fully; placement unchecked (the data hub's serialize/re-parse can move it into `<body>`). Accepted risk: a page can forge a note on a page the builder never touched (same trust as every footprint). Never a pick candidate, never in copy-all or the parity table.
- Copy: served verdict kept ("Active"); "Disabled in this tab by the Exclusion Builder" / Defer page-off "Off in this tab: an Exclusion Builder row stops WP Rocket deferring" / "N excluded by the Exclusion Builder"; feature-wide/page-off counts as Inactive in the P6G.12 filter; lazy-image count = images actually lazy-loaded; strip line "Exclusion Builder rewrote this page" + closed-pill glyph and name suffix ", rewritten by the Exclusion Builder". Copy declared once in `lib/detection/hud.ts`.

## WP Rocket parity (P10K)

- **Reference:** WP Rocket 3.23.5.1 + WordPress 7.1.3. Only the settings-form save path is mirrored (Abilities `SetOption`, import, `update_option`, third-party `pre_update_option` callbacks are out of scope). ALR has no settings field (`rocket_lrc_exclusions` filter + remote dynamic list): its rows are identity at save.
- **Stored-form rule (2026-10-22):** while edited a row is the user's text; on commit (focus leaves, paste/restore arrival, before Apply) it becomes WP Rocket's stored form with a per-row note "WP Rocket stores this as `…` (you typed `…`)"; rows WP Rocket drops (empty, `"0"`, duplicate — the rows already in the lane win —, `pcre-invalid`) leave the draft with an announced lane note. Draft, set, persistence, Apply and copy-all all hold the stored form. Unverified save outcomes keep their verified-stage form and say so; the three safe-mode rows stay with a conditional note (safe mode is unknowable from the page).
- **Save chain** (`field-text.ts`, one declaring site): split → PHP trim → drop empty/`"0"` → `sanitize_text_field` port (invalid UTF-8 drops the row, unclosed `<` run escaped, tags/script blocks stripped, whitespace collapsed, `%xx` loop) → Delay `rocket_clean_wildcards` (**every** `*` → `(.*)`, so `\*` breaks and the row is dropped) → first-occurrence dedupe → Delay/Defer drop rows failing PCRE compile.
- **Runtime matching:** Delay = each row alone (first hit), `+`/`?ver`/`#` escaped (every `+` quantifier becomes literal), ASCII-`i`, subject = the rebuilt **pre-delay** element; Defer = all rows joined `#(r1|r2…)#i` over the raw `src` value (a joined pattern that fails to compile or consumes `dummy-string` turns Defer off for the page: `joined-page-off`); Lazyload = case-sensitive literal over `atts` + trimmed `src`; ALR = ASCII-case-insensitive literal over the opening tag as libxml re-serializes it, three element levels, processed tags only, subtree skipped, later hashes re-keyed.
- **PCRE → JS:** fail closed. Rows translate to byte-string matchers (each UTF-8 byte → one code unit, ASCII letters expanded, never JS `i`) proven equal to `preg_match` on PCRE2 10.44 and 10.49; anything unproven is a row problem. Exact only for UTF-8 pages (WordPress default).
- **Problem classification (O1/O2 decided 2026-10-22):** **warn and apply** — `match-all` (`(?a)`-style option letters, empty alternatives/rows) and Defer `joined-page-off` (preview = WP Rocket deferring nothing); **block** — `pcre-only`, `pcre-invalid`, `joined-changes-matching`, `backtracking-risk`, wire caps. Background prevalidation and overlay agree on problems and warnings. O3 safe-mode conditional note; O4 byte-string translation; O5 polynomial rows accepted (budget names the row); O6 picked rows spell literal `+ ? * < %` (and edge spaces/tab/CR/LF, a lone `0`) as `\xHH`.
- **Feature-wide disables:** Delay JS restores every delayed script and removes its three controller scripts; ALR removes `data-wpr-lazyrender` + `rocket-lazyrender-inline-css` only (no lazy-render runner asset exists — plugin zip grep). Delay candidacy reads the delay-type vocabulary by substring (`;charset=` suffixes match); `data-rocket-status` is inert for served HTML. Pipeline order: inline-jQuery replay → Delay → Defer → ALR → Lazyload (order owned by `EXCLUSION_FEATURES`), then the marker step; restored elements are stamped `data-wpr-fdt-excluded` (CSV, `, `), doctype kept.
- **Memo bounds** (`utils/bounded-memo.ts`): memos keep detached string copies and weigh retained bytes — rows split from a field are views that pinned the whole field text (300 edits of a 500-row lane retained 58 MiB before; 0.94 MiB after).
- **Defer inline jQuery:** WP Rocket skips wrapping inline jQuery when the joined exclusion text matches `/(jquery(?:.*)?\.js)/i` — across rows, including live rows the tool cannot read. Engine unwraps only when certain (a draft row matches alone); otherwise leaves as served and counts `undetermined`; never re-wraps.
- **Parity table:** `lib/exclusion-builder/wp-rocket-parity.fixtures.json`, 369 rows (282 match + 87 save), expected outputs from the real plugin under `php -n`; `pnpm test` replays it without PHP; `pnpm parity:wp-rocket` re-derives byte-for-byte (`--write` regenerates). Header pins plugin zip sha256, WP zip sha1, PHP/PCRE2/libxml. The local zip is never byte-reproducible (build mtimes, per-build `composer.lock`).
- **CI job** (`.github/workflows/wp-rocket-parity.yml`, informational, not required): APVM v3.3.0 (checksum-pinned) builds the table's tag; harness in a digest-pinned `php:8.4-cli-bookworm` image (PHP 8.4.27 / PCRE2 10.44 / libxml 2.9.14), offline — distro PHPs cannot reproduce it (ubuntu-24.04 PCRE2 10.42 rejects the 10.43+ option letters; 26.04 libxml 2.15.2 differs); `--ci` fails on "table stale" or "reference drift" (vendored packages), `--compare` warns only against `tag:latest-stable`. Triggers: PRs and pushes to `main`/`develop`/`feat/**` touching parity paths, weekly cron, dispatch (cron/dispatch only once the file is on `develop`). First green run 39862491481. Older WP Rocket tags may not build (composer conflicts).
- **Named residuals** (fixture-pinned, never silent): Delay rebuild spacing/valueless-`type`/tag spelling shapes; copies of scripts inside comments or attribute values; Lazyload quoted `>` (`alt="a>b"` breaks WP Rocket's own markup) and pages without `<noscript>` (`approximate`); picture/iframe/CSS-background lazyload not previewed; ALR unknown dynamic list, `rocket_lrc_*` filters assumed default, non-Latin single-byte/UTF-16 pages; Defer remote `defer_js_external_exclusions` not modeled; inline-jQuery r1 (source already in wrapper form) and r2b/r2c/r4 shapes flagged or left as served; source markup already spelling WP Rocket's markers.
