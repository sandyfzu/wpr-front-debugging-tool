# Audit — WP Rocket feature coverage (detection & DevTools tooling)

**Status:** audited 2026-10-07 — **outcome: approved; all items folded into the self-contained phase P14.5** ([`15b-phase-14-5-coverage-and-tooling.md`](./15b-phase-14-5-coverage-and-tooling.md), the last phase before release) — see §7. This file remains the research record. **Plugin:** `wp-media/wp-rocket` `develop` @ **3.23.5.1** (per `wp-rocket.php` — two generations past the 3.19 facts the plan was built on; every drift surfaced is recorded below).

## 1. Method

- **Settings inventory:** `inc/Engine/Admin/Settings/Page.php` field registrations + `views/settings/**` + `inc/Engine/Support/Data.php` (the plugin's own active-options map) + `inc/Engine/Support/Meta.php` (generator-meta keys, exact conditions read).
- **Footprints:** each feature's engine controller, read with the specific emission lines cited in this doc. Nothing below is asserted from memory; anything not read is marked **to verify**.
- **Baseline:** this port's registry = 13 rows (`lib/wp-rocket/types.ts`) + P1.1's 4 + P11's 2 → **19 checks**; the merged detection pass (P11) adds generator-meta as an evidence layer.
- **Scope agreed for this audit (user, 2026-10-07):** detection may use page DOM + captured response headers + fetches (probes); tool proposals are all ranked in §5; footprints verified against plugin source + KB (live-site probing stays a phase task).

Legend for the matrix: ✅ row exists today · 📋 planned (P11/P1.1) · 🆕 proposed by this audit · ⛔ no page evidence · 🔭 option-state only via the Diagnoser report (P7 renders it).

## 3. Meta-comment reality check (what P11's `FEATURE_META_KEYS` gets right and wrong)
