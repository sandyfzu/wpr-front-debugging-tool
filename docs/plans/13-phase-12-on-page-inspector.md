### P12C — Persisted drag/brief reconciliation

Depends:B. Parallel:P13/P14. Size:S. Shipped 2026-10-28.

- [x] Persist on settled drop; restore/reclamp through the existing resting containment seam. No new geometry.
  - **Representation:** the stored `{x,y}` is the chrome's drag translate = offset from the bottom-right 16/16 stylesheet anchor (the P12B `local:detection-widget-positions` contract, unchanged). Why: pill and card share that corner inside one chrome, so one value serves either shape (the card opens from the dropped corner, as at drop time); the default corner stays edge-anchored across viewport changes, and any other placement is re-clamped by the same 4 px containment the drag uses (a far top-left park on a wide screen lands top-left on a narrow one). Proportional/nearest-edge forms were not taken: they need a second geometry model and a storage-contract change for no case the clamp does not already hold.
  - **Persist:** `settle()` now returns the committed translate once per moved drag (null for slop clicks, stray pointers, dead chrome); pointerup and the capture-loss settle both route through it, so release-then-loss writes once. Cancels (Escape, contextmenu, pointercancel, second pointer) never write. Save is fire-and-forget but caught: failure → `[WPR FDT] [inspector]` warn with the position, widget unchanged. At-rest re-clamps (resize, card growth) are not written — the stored value is the user's drop, the clamp is per viewport.
  - **Restore:** the page's one read starts beside the body wait (first show); after `show()` → `'shown'`, `await Promise.all([surface.rendered(), read])` → `restore(position)` (refused, not deferred, mid-press or after a settled moved drop; a canceled drag never blocks it) → synchronous `reclamp()` (resting box = layout offsets, valid mid-entrance) → containment cycle for later growth. Lands in the render's task, so the first frame already shows the clamped position when the read wins (otherwise one instant move). Ordering: the read (local area) is issued before the body wait, host creation (CSS fetch) and the appearance read (sync area) the render awaits. Nothing orders replies across areas, and the render is never held for the read, so a read that loses moves the chrome once, instantly; the e2e accepts either path and annotates `restore-race`. Corrupt/failed read → anchor (warn on failure). A drop during the in-flight read wins. Hide → show re-mounts at this page's last drop (in memory). Collapse stays session-only. **No live cross-tab follow** (chosen): other tabs of the origin pick a drop up at their next load.
