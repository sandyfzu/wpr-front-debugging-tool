### Origin state (reuse, do not fork)

`lib/storage/inspector-origins.ts`, **sync:inspector-origins**, origin→enabled; context-menu **Toggle the detection widget on this site** writes clicked document's origin. This is P12's established item, not a temporary alternative to resurrecting local:on-page-inspector.

Resolution (owner's 2026-10-17 turn-on): an explicit per-origin entry wins over the global default in **both** polarities; origins without an entry follow the `features.onPageInspector` option (on by default; [P12B](#p12b--final-registrystatetoggle-integration)). The toggle flips the site's **current effective state** (a right-click always changes the site's behavior; under default-on an unconfigured right-click writes `{enabled:false}`), never storage absence, and explicit entries outlive a later default change.

Original200-origin cap was false under sync8192-byte/item quota. ### P12B — Final registry/state/toggle integration

Depends:P11/P9 (existing P12A baseline; the popup's Detections row lands additively at deferred P8). Parallel:P13/P14. Size:S–M.

- [x] Repoint/delete provisional strip registry; native names/group ordering from hud, full-name/unsure reasons (done in P11C). No old SHGF/OCI/ALR tool-internal short labels restored.
- [x] Storage/eviction + position contract — shipped 2026-10-28.
  - **Recency defect fixed:** Chromium returns stored objects with keys **sorted** (verified live: `{zeta, alpha, mid}` read back `alpha, mid, zeta`; `chrome.storage.sync` reported 8192/102400/512 items/120 writes/min/1800/h), so P12A's "insertion-oldest" trim evicted alphabetically after one round trip. Entries now carry a write-recency rank `used` (map's max + 1, a counter — a few digits vs a 13-digit timestamp; bumped on writes only, reads never write: sync write-rate quotas). Shared primitives `lib/storage/recency-map.ts` (`parseRecency`, `nextRecency`, `itemBytes` = bare key + JSON, the Chrome/MDN per-item measure, and `trimToByteBudget`: least-recent first, map-order ties, incremental accounting, never evicts the last entry so an oversized singleton reaches the platform and its rejection propagates).
  - **`sync:inspector-origins`:** origin → `{ enabled, used? }`. Older `{ enabled }` entries parse unchanged (rank least recent); broken `used` dropped (entry kept); unknown fields tolerated, not carried; corrupt → no entries. Trimmed to **7168 B** (1 KiB under 8192): ~60 B/typical entry → ~120 overrides; 253-char hosts → ~24.
  - **Position: sibling item `sync:inspector-positions`** (`lib/storage/inspector-positions.ts`), origin → `{ x, y, used? }` (integer CSS px offset from the stylesheet anchor = the drag translate; rounded, finite, |v| ≤ 32768, else the entry is dropped → anchor). Same 7168 B budget, ~115 positions. Why not the same item: drops are frequent and per-device, overrides rare and deliberate — one 8 KiB item would let dragging across sites evict explicit per-site choices (~90 combined entries vs ~120 + ~115), and the content script's drop write would race the background toggle over one read-modify-write. Enabled state still has exactly one store. `saveInspectorPosition` throws `RangeError` on insane input/empty origin; `getInspectorPosition` → null on none/corrupt. **Not wired yet — P12C persists on settled drop and restores through the containment seam.** Sync write quota trade-off for P12C: one write per settled moved drop only.
- [x] Global default option — shipped 2026-10-28. `features.onPageInspector` (`lib/storage/options.ts`, default **true**, validated/seeded like the other flags) replaces `INSPECTOR_DEFAULT_ENABLED` (deleted); `effectiveInspectorEnabled(origins, origin, default)` keeps entry-over-default in both polarities; `toggleInspectorOrigin` reads both items and flips the **effective** state (context menu + palette unchanged callers; the popup row at P8 calls the same helper). Options row (`lib/options/registry.ts`, drafted boolean, `onPage` cascade from the gate, before the badge): **"Show the detection widget on pages by default"** — the menu/palette vocabulary ("Toggle the detection widget on this site"), not the brief's "chip"; description names that toggle as the per-site override. Applies on Save; the widget follows the existing `sync:options` watch (no new channel): arm-first watches on both items, boot read applied per item only when no write raced it, effective state resolved once both are known; unrelated options writes resolve to the same value and are skipped.
- [x] Collapse/session visibility, disabled origin, cleanup — shipped 2026-10-28. With the shortcut dropped (owner 2026-10-28; Alt+H open for [P15D](./16-phase-15-hardening-release.md#p15d--docsrelease)), "session visibility" has no separate control: visibility is the persisted effective state; **collapse** (card ↔ pill, SB-D11) stays session-local — never stored, a hide closes it, a fresh boot starts collapsed (now pinned). **Disabled origin:** no shadow UI, no hub read, no page listener — the window `resize` containment trigger moved from per-widget to per-mount (it was the one listener a hidden widget still kept). **Cleanup:** both watches unsubscribe on invalidation; WXT removes the host; per-mount listeners ride the mount signal.
  - **Same origin, many tabs:** every tab's top-frame content script watches both sync items, so a toggle or option flip mounts/hides the widget on all open tabs of that origin live; collapse and (until P12C) drag position stay per tab. The isolated script runs top-frame only, so frames never get a widget. **Incognito:** origin is the key, browser mode is not. Chromium's default `incognito: "spanning"` (unset in `wxt.config.ts`) runs one extension instance with one storage for both window kinds once the user allows the extension in Incognito; Firefox has no split mode and needs the private-windows permission. Docs-derived, not runtime-verified (stays in the manual list below).
