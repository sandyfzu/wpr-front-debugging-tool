### P15F — "What's new" page on update

Depends:E.2 (logo), P15C (shipped UI final). Parallel:E.3. Effort:M. Difficulty:medium. **Release-critical** (owner 2026-11-20): existing users updating to 3.0.0 see a page presenting the new version.

**Risks → mitigation.** Page opens on every browser start / service-worker wake (spam) → once per announced version, stored marker. Opens for a fresh install as "new version" → install path never announces (seed the marker). Missed event (Chrome disables the update until the `debugger` warning is accepted; `onInstalled` may not reach a disabled extension — **verify at execution**) → startup check against the marker catches it once re-enabled. Store rejection (unexpected tabs, remote content) → bundled page, no remote code/analytics, behavior disclosed in the listing, verified in the P15D store-policy row for both stores. Copy drifting from what ships → notes data from one registry, reviewed in the P15C ledger.

- [ ] **Release-notes registry** (`lib/release-notes/`, pure, one declaring site), **versioned by the extension's own version** (the manifest/`package.json` version, never a separate page version): one row per announced extension version — version, date, headline, highlights (title, one line, how to reach it, screenshot ids), changes users must know (new `debugger` permission + why; removed popup/Diagnoser), links (support/docs). Only rows flagged `announce` open the page (majors/notable minors, never routine patches). The page shows the running version (read from the manifest) with its row first; earlier announced rows stay below as collapsed history, so each future release only adds a row + its screenshots.
- [ ] **3.0.0 content — the really new and important things lead**, each as a highlight card with its screenshot and **how to open it** (paths verified on the shipped build at execution, never from memory: panel top bar/nav, command palette Alt/⌥+K, context menus, toolbar click): Exclusion Builder (in-page overlay, apply/reset/stop) + WP Rocket simulation; RUCSS Tester; Beacon Tester (+ LCP/script/web-vitals analysis); the on-page detection chip/widgets (detection strip, site badge); the toolbar icon's status dot (what each state means, per its tooltip); command palette. Then **WPR Inspector deprecated**: its features now live here — name where each one went, and tell users they can uninstall it. Lower-priority improvements as a short list, never as cards.
- [ ] **Screenshots — taken by the implementing agent**, not the owner: one capture script (Playwright over the built extension + docker site, reusing the e2e harness; shared with the P15E.3 store screenshots) shoots each highlight on the real shipped UI, light + dark (page shows the one matching the resolved appearance), no customer data/real-site URLs; optimized (WebP/PNG, measured) and bundled with the page (no remote images); re-shot after P15C so copy in them is final. Each image gets meaningful `alt` text, fixed width/height (no layout shift), lazy-loaded below the fold, counted in the page's budgets row.
- [ ] **Decision function** (pure, unit-tested matrix): inputs = `onInstalled` reason (`install`/`update`/`browser_update`/`chrome_update`/`shared_module_update`), `previousVersion`, current manifest version, stored marker (`local:` last announced version), user opt-out → open the page for the newest announced version with `previous < v ≤ current` and `v > marker`, else nothing. `install` seeds the marker silently. Upgrades from the old build (no marker; `previousVersion` 2.x) announce 3.0.0. Run on `onInstalled` and once at background start (missed-event catch-up); idempotent — the marker is written before/with the open so a crash can't loop. Malformed versions/marker → no page + warn, never throw.
- [ ] **Opening:** `tabs.create({ url: whats-new.html, active: true })` (no `tabs` permission needed) in the last-focused normal window; never in incognito; failure logged, marker still respects "once". Verify `onInstalled` registration is synchronous at top level (wake-safe).
- [ ] **Page** (`entrypoints/whats-new/`, unlisted extension page, both builds): logo + "WPR Front Debugging Tool" + the running version as headline, highlight cards (with screenshots) from the registry, earlier versions as history, "what changed" (permission explained plainly), buttons: open options, how to open the DevTools panel (Chrome cannot open DevTools for the user — show the shortcut per platform), support link; footer opt-out switch "Show what's new after updates" (also in options, one synced setting, default on) + a "What's new" link in options to reopen it any time. Theme System/Light/Dark per AGENTS, `docs/ui-ux-bar.md` (§D receipts, 320 px), no remote fonts/images/scripts, budgets row (both builds, `required`).
- [ ] **Tests:** decision matrix units (every reason, equal/lower/higher versions, multi-version jumps, missing/corrupt marker, opt-out, catch-up path, double event), registry shape test (versions valid + strictly ordered, announced row exists for `package.json` version at release, every screenshot id resolves to a bundled image in both palettes), page component tests (themes, opt-out writes the setting), e2e: drive the decision via the worker (fake `previousVersion`) → exactly one tab with the page; second wake → none. Owner manual: real store-style update 2.2.x → 3.0.0 on Chrome (incl. the disabled-until-accepted path) and Firefox.
