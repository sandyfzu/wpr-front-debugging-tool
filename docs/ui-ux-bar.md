# UI/UX bar — every user-facing surface

**Status:** binding, the single declaring site of the project's UI/UX quality bar (owner mandate 2026-10-14: refined, fast, responsive, beautiful, motion that feels good — never a circus — and best-practice UX). **Applies to:** the devtools panel (shell + pages), options, exclusion builder, every injected UI (strips, badges, overlays, side-by-side chrome) and any future surface. **Linked from:** `AGENTS.md` (Non-negotiable rules → UI/UX bar) and the master plan's design-bar principle; phase docs cite rule ids (`M-2`, `D-1`…) and keep only surface-specific decisions.

**Sources it builds on (never contradicts):** the [binding design decisions](./plans/design-decisions.md) (`UX-Dn`/`SB-Dn`; precedence: plugin/KB naming > design decisions > this bar > phase docs), the tokens in `assets/css/tokens.css` (+ the Tailwind mapping in `theme.css`), and the primitives in `components/ui/`. Changing a value here = edit this file (date-stamped line in §Change log) in the same commit as the code that moves (dated owner exception for P23: §Change log 2026-11-18); a phase doc never re-declares a value.

**Reuse before invention.** A surface adds no token, keyframe or primitive ad hoc: use what ships; a real gap becomes a design-system change (token/primitive + its tests) owned by the phase that needs it, or a surface-local solution recorded as a **promotion candidate** in that phase's receipts.

## L — Layout & responsiveness

- **L-1 Container queries, not viewport queries.** Each surface's root (or region root) is the `@container`; viewport `sm:`/`md:`/`lg:`/`xl:` variants are banned in panel/injected code (devtools docking and host pages make the viewport meaningless). Layout tiers have one declaring site — the named container sizes `--container-regular: 480px` / `--container-wide: 768px` / `--container-split: 830px` in `assets/css/theme.css`'s `@theme` — and surfaces write the generated variants, never the pixel literals: **compact (no variant, `< 480px`) · regular `@regular:` · wide `@wide:`** (`@max-regular:` for compact-only; Tailwind compiles them to `@container (width >= 480px)` etc.), plus **`@split`** = the content width from which a list shows its detail pane (`UX-D17`; its JS rule is mirrored by the token, sync-guarded). **Shell rules** (panel width, measured by a `ResizeObserver` on the shell element — never a viewport query; one JS constant each, CSS sync guard where CSS reads it): sidebar labeled at shell width **≥ 1080 px**, else the rail (`UX-D2`); top bar at full width from a **760 px** panel, below it folds into its "⋯" menu (`UX-D8`), and at every width a measured fold keeps each secondary part whole or gone — address, server, cache age, freshness text, then the brand mark drop into "⋯" in that order until the rest fits (natural widths, one `ResizeObserver`; "⋯" shows whenever anything folds; the WP Rocket + cache pills and the controls never fold, eliding only once every part is folded; three texts have a designed cap and elide only past it — WP Rocket version label 12rem, server value 18rem, address 16rem — their title keeps them whole); a pinned labeled sidebar holds down to that same top-bar threshold (one shared constant), the rail is forced below it (`UX-D2`). A query reads its **own container's content box**, never the panel width: the container sits outside any padding (panel pages: `PageFrame`'s unpadded root, so a page's breakpoints measure the content region = panel − sidebar, **208 px labeled / 52 px rail**; beside the rail regular from ≈ 532 px, wide from ≈ 820 px, split from ≈ 882 px). `D-1`'s widths are panel widths — checkpoints, not breakpoints.
- **L-2 Geometry floors.** Panel: from a 320 px panel (≈ 268 px content beside the 52 px rail) up, at every docking (`UX-D8`). Other surfaces declare their supported range in their phase doc (options tab widths ≥ 320 px, injected UI — the exclusion builder overlay included — at the host's narrowest viewport) and meet the same rules inside it.
- **L-3 Behavior by width.** Compact: one column; actions wrap under the title; chip groups wrap (never a horizontal chip scroller); row meta stacks under the row's main line; a copy control goes icon-only (accessible name kept) only where that truly saves title-row space — a page's primary action keeps its visible label at every width. **Lists** (`UX-D17`/`UX-D18`): compact rows stack (name + size / preview / chips line) and facets fold into a "Filters" button + bottom sheet; `@regular`+ rows use columns; below `@split` the detail is a drill-in view, from `@split` a side pane taking **half the list width** (floors: pane **350 px**, list **480 px** — `@split` = their sum), resized by its splitter (drag, ←/→ 16 px, Home/End, double-click resets; the dragged share persists per device and every list follows it). Every detail is **one column** (chips, source tile, facts, then code — code always last, each full width) in both views; detail code opens wrapped when minified (a line > 160 chars) and caps its area at the view's height less 3.5 rem (floor 10 rem; never taller than the view, nor than the panel less 7 rem), scrolling inside past it; a wheel over half-shown code scrolls the panel (when the view reaches below it) and the view until the code is whole on screen, then the code — the rest of that tick included; a wheel the browser hands over non-cancelable stays the browser's. Master–detail list routes keep the standard 80 rem canvas (controls, rows and summary one block) and span the whole content width while a detail is open (the pane takes the room; row content caps at 80 rem). Card grids (Detections "Cards" mode only): `grid gap-2 grid-cols-[repeat(auto-fill,minmax(15rem,1fr))]` (1→2→3→4+ columns, no breakpoint drift; 15 rem keeps feature names on ≤ 2 lines beside a status badge). A long grid of small cards renders at compact as **one grouped surface of calm rows** (T-3 row gap inside one bordered surface, no `divide-y`, the cards' own borders dropped) — a stack of a dozen bordered cards in a floor-width column (L-2) is chrome, not content. T-3's calm-row rule binds the Detections List/Grouped rows too.
- **L-4 No horizontal scroll** on any surface's content region at any supported width; the only sanctioned horizontal scroller is a code block with wrap off. Long URLs `truncate` (full text in `title` + the accessible name); payload values (e.g. header values) `break-all`.
- **L-5 Heights.** Surfaces lose height in a declared order (panel: `UX-D15`); a list's scroller has a floor (`min-h-48` on panel pages; with a side pane open 20 rem, or the panel's content view when shorter) below which the region's own scroll takes over — never a clipped list, never nested scrollers when one scroller can hold the content (a detail's capped code block is the sanctioned inner scroller).

## T — Typography & density

- **T-1 Scale.** `text-base` page `h1` only · `text-sm` section `h2` · `text-xs` (12 px) body, list row names `font-semibold` · `text-2xs` (11 px) meta/chips/code, caps labels (column headers, sidebar groups) `uppercase tracking-wide` · stat tiles only: `text-stat` 20/24 px (main number), `text-tile` 15/20 px (value). Nothing else on data surfaces — the two tile roles are the only additions (the theme overrides `2xs/xs/sm` for devtools density).
- **T-2 Roles.** `fg-primary` content, `fg-secondary` supporting, `fg-muted` labels/meta only. URLs, code, header names/values, versions, identifiers → `font-mono`; every count → `tabular-nums`.
- **T-3 Density without cramping.** List rows: two-line min 58 px, one-line min 36 px, 4 px between rows, 14 px inner padding, **no hairlines between rows** (interactive rows tint on hover `surface-3` / selected `accent-soft` instead); ≤ 2 visible state chips + "+N"; never a card per row; cards keep `Card`'s `p-2.5`; spacing rhythm `gap-3` between sections, `gap-1.5` inside. Hit areas ≥ 24×24 CSS px always (WCAG 2.5.8 — `Button`/`IconButton` sizes comply; never shrink them).
- **T-4 One heading tree.** Exactly one `h1` per page (`PageHeader` on panel pages), no skipped levels.

## M — Motion (closed list; values pinned)

- **M-1 Tokens only.** `--motion-fast` 120 ms · `--motion-base` 180 ms · `--motion-slow` 280 ms; `--ease-standard` `cubic-bezier(0.2, 0, 0, 1)` · `--ease-entrance` `cubic-bezier(0, 0, 0.2, 1)`. No literal ms/easing in surface code (an injected feature may alias tokens locally, as `detection-widget.css` does).
- **M-2 The sanctioned moments** (Tailwind surfaces import the two constants from `components/ui/classes.ts` — landed there by P6A.1, never re-typed; shadow-root CSS writes the same tokens):

  | Moment                                                                           | Mechanism                                                                                                                             | Values                                               |
  | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
  | Page/view mount                                                                  | the panel's `.fdt-page` (`entrypoints/panel/style.css`); other pages the same keyframe shape                                          | `--motion-base`, `--ease-entrance`, 4 px rise + fade |
  | Revealed content (disclosure body, an async result's first paint)                | `MOTION_REVEAL = 'transition-opacity duration-[var(--motion-base)] ease-[var(--ease-entrance)] starting:opacity-0'`                   | 180 ms fade on insert (`@starting-style`)            |
  | Disclosure chevron                                                               | `MOTION_TURN = 'transition-transform duration-[var(--motion-fast)] ease-[var(--ease-standard)]'` + `rotate-90`/`rotate-180` when open | 120 ms                                               |
  | Floating chrome open/close (injected strips, overlays, the panel's filter sheet) | class-driven transitions, state never waits on `transitionend` (master #49)                                                           | enter `--motion-slow`, exit `--motion-base`          |
  | List detail pane enter (`UX-D17`)                                                | opacity + `translateX`                                                                                                                | 8 px, `--motion-base`, `--ease-entrance`             |
  | Drill-in view swap (list ↔ detail)                                               | the page/view mount keyframe                                                                                                          | as page mount                                        |

- **M-3 Everything else is instant:** hover/press colors (no primitive transitions them), data swaps (filter, search, refresh), counts (no tweening), expand/collapse heights, sidebar fold/unfold (no width animation, M-4).
- **M-4 Properties.** Animate `opacity`/`transform` only (plus `box-shadow`/`border-color` for the lift); never `height`/`max-height`/`width`/`top`/`margin`.
- **M-5 Bans.** Per-row/per-index entrances (virtual rows remount on scroll — any row fade, `MOTION_REVEAL` included, replays on every scroll); stagger; `transition-all`; infinite loops except during a real wait (shipped: `Skeleton`'s pulse, `Button`'s busy spinner, the detection widget's scanning pulse); JS `scrollIntoView`/`scrollTo` with `behavior: 'smooth'` (the reduced-motion reset cannot reach an explicit JS option — use the default or `block: 'nearest'`).
- **M-6 Reduced motion.** `prefers-reduced-motion: reduce` drops every animation and transition on every surface — one rule in `tokens.css` (`animation-name`/`transition-property: none`, durations kept collapsed to 0.01 ms for duration-derived timers), loaded by the pages through `theme.css` and by each injected UI's shadow root (`*` stays inside the shadow tree) — so an entrance never paints its `from` frame and `getAnimations()` stays empty. Surfaces verify it (`panel-reduced-motion`, `injected-reduced-motion`), never re-implement it, and never encode state in a transition or its delay (reduced motion must not strand a container).

## S — States (no dead ends `UX-D9`, no theater `UX-D6`)

- **S-1 Every async surface has a state matrix**, listed in its TSDoc and tested state by state: loading (only for a real wait — `Skeleton` compositions shaped like the final layout, never a timer), error (`ErrorState` naming the failure + Retry; extension-context-invalidated named with its remedy), **feature absent**, **empty**, **filtered-empty** (names the filter and query, offers `Clear search` / `Show all` / `Clear filters` (facets + search; `NoMatchesAction` `'clear-filters'`) — one click back), populated.
- **S-2 Refresh is invisible.** A data refresh keeps the view mounted and its UI state (selection, query, expanded rows, open disclosures, scroll, focus) — no flash, no surface-level spinner when a freshness signal exists elsewhere (`UX-D1`, `UX-D5`). Row UI state lives with the owner of the list, keyed by row id, never in a virtual row (rows unmount on scroll).
- **S-3 Copy for states:** a title line + one sentence (what would be here / what failed) + a forward action when one exists. Side effects (copy, save, export) confirm with a toast; failures toast the remedy.

## K — Keyboard, focus, ARIA (`UX-D3`)

**Scope (owner 2026-10-27): accessibility is minimal and effort-free — zero screen-reader support** (internal support-team tool). Required only where free: semantic HTML (real `button`/`a`/headings/labels) and what `components/ui` primitives ship (native/Kobalte keyboard behavior, `FOCUS_RING`, the virtual list's built-in roles). No new a11y work: no live regions/announcements, SR/real-AT (NVDA/JAWS/VoiceOver) checks, ARIA research, keyboard walks or new axe assertions. Shipped a11y code and existing axe assertions stay as they are (never removed or weakened). Rules below marked _dropped_ are not required for new work; ids stay for references.

- **K-1** Native controls and primitives give keyboard reach; Esc closes overlays (dialog primitives) and clears search. List rows (`UX-D17`): ↑/↓ move selection (pane) or focus (drill-in), Enter/Space opens, Esc closes the pane / goes Back; never taken from editable fields. `/` keeps opening the shortcuts overlay — no search key is added and search fields show no key hint. Full keyboard-completeness and Tab-order audits: _dropped (owner 2026-10-27)_.
- **K-2** Every interactive element carries `FOCUS_RING` (`components/ui/classes.ts`); focus never moves on data changes. Collapse-keeps-focus and route-switch-lands-on-`h1`: shipped behavior kept, not required for new work (owner 2026-10-27).
- **K-3** Patterns: tabs/menus/combobox/dialog via the `components/ui` wrappers only (they carry their ARIA for free); hand-written ARIA (disclosure `aria-expanded`/`aria-controls`, virtual-row `aria-setsize`/`aria-posinset`) and the ≥ 200-row sequential-Tab traversal: _dropped (owner 2026-10-27)_ — kept where shipped.
- **K-4** _Dropped (owner 2026-10-27: no screen-reader support)._ Was: result-count changes announce once via `sr-only role="status"`; the shipped announcement code stays, no new announcements.
- **K-5** Status is never color alone (vocabulary icon or text, `UX-D7`); external links open in a new tab with `rel="noopener noreferrer"` and an icon (the "(opens in a new tab)" accessible-name suffix: _dropped_ for new links, owner 2026-10-27); controls are never hover-revealed only.
- **K-6** Hover affordances only on controls: a non-interactive card never lifts, changes cursor or takes a tab stop.

## C — Color, contrast, themes

- **C-1 Tokens only** — no hex/`rgb()`, no `opacity-*`/`/NN` alpha on text, no gradient text on data. `assets/css/theme.test.ts` pins every `fg-*`/`accent`/`status-*` text token at AA 4.5:1 on every `surface-*` and `status-*-soft` background (`fg-*`/`accent` also on `accent-soft`) in both palettes and both token scopes (shared, and the extension-page block panel + options resolve), so a token pair passes by construction; contrast audits beyond the tokens are not required (owner 2026-10-27). Control boundaries (text fields, switch tracks) use `line-strong`, pinned ≥ 3:1 on every surface (WCAG 1.4.11; hover steps to `fg-muted`); `line-0`…`line-4` are decorative hairlines (cards, dividers, popover edges, text-labelled buttons, tiles and segments), below 3:1 by design.
- **C-2 One status vocabulary** (`UX-D7`) through `StatusBadge`/`Badge` and the `STATUS_*` tables; an optional feature being off is `neutral`, never `error`.
- **C-3 Themes:** verified in `system`, `dark`, `light`, switched live (AGENTS.md UI-themes rule); injected UIs honor it inside their shadow roots.

## P — Performance (`UX-D13`)

- **P-1** One source, one `createMemo` chain (rows → filtered rows → counts in one pass); nothing derived in row renderers; no `createEffect` writing what a memo can derive; stable row keys.
- **P-2** Lists whose source can exceed 100 rows always render through `components/ui/virtual-list` (one code path, no count-switched dual rendering — `UX-D10`). Per-row cost O(rendered rows): no Kobalte `Tooltip` per virtual row (use `title`), no per-row observers beyond `CodeBlock`'s own. Rows render text only; code highlights only in a detail view (calm lists, `UX-D17`).
- **P-3** On a 5,000-row fixture, filter change / search commit / view switch: no long task > 50 ms, TBT < 200 ms. Heavy deps load lazily and heavy work leaves the main thread: shiki runs only in `CodeBlock`'s highlight Web Worker, each block time-boxed (a runaway block's worker is terminated and the block stays plain text), and the main thread only mounts bounded markup; every surface stays under its `scripts/budgets.json` row and receipts its delta.
- **P-4** Images and other remote fetches from extension surfaces are lazy, fixed-size (zero layout shift) and `referrerpolicy="no-referrer"`.

## W — Words (`UX-D12`)

- **W-1** Sentence case; feature names only from the option map/verified labels (never re-typed); digits for numbers; present tense; no "please", no exclamation marks, no blame; toasts `"<Thing> copied"`.
- **W-2** Every string delta vs a reference surface is listed in the phase's receipts; P15's copy sweep owns final wording.
- **W-3** Vocabulary: US spelling ("Analyze", "canceled"); feature names cased as declared (`Exclusion Builder`, `Known Conflicts`, `RUCSS Tester`, `Beacon Tester`, `LazyLoad` = `SHORT_LABEL_LAZYLOAD`), strip chips in Title Case; verb forms open ("lazy loaded", "Not lazy loaded"), never "lazyloaded"; "fetched" = when the panel read the page's data, "captured" = what was observed or recorded as the page loaded (response headers, cookies); one failure, one headline (shared tables, e.g. the panel ask-miss titles).

## D — Definition of done (every UI change, receipted in its phase doc)

- **D-1 Widths:** the surface's floor, 480, 768 and a wide size (panel: 320 / 420 / 480 / 760 / 1100 / 1280 px, docked right and bottom): the content region never scrolls horizontally (`scrollWidth === clientWidth`), every control reachable.
- **D-2 Themes + motion:** `system`/dark/light, then `prefers-reduced-motion: reduce` emulated — `document.getAnimations()` (or the shadow root's) empty after mount.
- **D-3** _Keyboard-only walk: dropped (owner 2026-10-27)._ New controls show `FOCUS_RING` (K-2).
- **D-4** _New axe audits: dropped (owner 2026-10-27)._ Existing axe assertions (`panel-a11y` and the suites that already audit) stay green and unweakened.
- **D-5 Refresh** keeps UI state (S-2).
- **D-6 Grep gate** over the change's own files, empty: `rg -n "#[0-9a-fA-F]{3,8}\b|rgba?\(|transition-all|animate-|duration-[0-9]|\b(sm|md|lg|xl):|behavior: 'smooth'" <files>` (shadow-root CSS: the colour and `transition-all`/smooth terms apply; hits on token definitions themselves are out of scope).
- **D-7 Performance:** where the surface lists rows, the P-3 check on the 5k fixture; budget delta receipted.
